# 백업 저장 확인을 묻지 않는다 — 되돌리기 토스트로 바꾼다 — 설계

**날짜:** 2026-08-06 **상태:** 승인됨(사용자), 구현 대기

리포트 화면의 인라인 확인 배너 두 개를 없앤다.

- **내보내기 확인** — "파일 앱(또는 다운로드 폴더)에 저장했나요? / 네, 저장했어요 / 아니요"를
  **묻지 않는다.** 대신 `lastExportedAt`을 즉시 기록하고, 「저장 안 했어요」 액션이 붙은
  토스트로 되돌릴 기회를 준다.
- **초기화 확인** — 같은 인라인 배너를 `confirmDialog` 오버레이로 옮긴다(가져오기와 동일한
  컴포넌트).

## 왜

### ① 인라인 배너는 이 앱에서 이미 소수파다

확인 흐름이 셋인데 모양이 둘로 갈려 있다. 가져오기(복구)는 `ui.ts`의 `confirmDialog`
오버레이를 쓰고, 내보내기 확인과 초기화 확인만 `#/report` 본문 안에 배너를 그린다. 배너는
페이지 흐름 속 다른 카드들과 섞여 "지금 답해야 하는 질문"으로 읽히지 않는다 —
스크린샷에서 「유형별 정답률」과 30일 경고 배지 바로 아래에 확인 버튼 두 개가 붙어 있는
것이 그 결과다.

### ② 내보내기 확인은 흔한 성공에 세금을 매겨 드문 실패를 잡는다

이 질문이 존재하는 이유는 UX 취향이 아니다. Download API에 완료 신호가 없어서
(`triggerDownload` 주석) 코드는 아빠가 실제로 파일 앱에 저장했는지 알 수 없다.
`lastExportedAt`은 30일 배지 — 서버 사본이 없는 이 앱의 **유일한 안전망** — 를 굴리므로,
무조건 갱신하면 네이티브 저장 시트를 취소했을 때 배지가 거짓말을 하고, 아예 갱신하지
않으면 배지가 영구히 떠서 무시하게 된다. 그래서 사람에게 한 번 물어 왔다.

진짜 설계 질문은 **"어떤 컴포넌트로 묻나"가 아니라 "모르는 값을 어느 쪽으로 기본
추정하나"**다. 지금 코드는 비관적이다 — 답하지 않으면 기록하지 않는다. 그런데 저장 시트
취소는 드물고 정상 저장이 압도적으로 흔하다. 비관적 기본값은 흔한 경로에 매번 탭 하나를
물리고, 반복되면 「네, 저장했어요」를 확인 없이 누르는 습관을 만들어 보증 자체가
형해화된다.

낙관적 기본값 + 되돌리기는 같은 보증을 유지하면서 정상 경로의 탭을 0으로 만든다.
**되돌릴 수 있는 한 물어볼 필요가 없다**는 것이 핵심이고, `lastExportedAt`은 되돌릴 수 있다.

### ③ 초기화는 반대다 — 모달이 맞는 자리

`resetAll`은 되돌릴 수 없다. 되돌릴 수 없는 것 앞에서는 흐름을 끊는 모달이 옳고,
가져오기 확인이 이미 그렇게 하고 있다(`tone: 'critical'`). 이쪽은 컴포넌트만 통일한다 —
문구·가드·`resetAll` 호출 방식은 그대로다.

## 검토했지만 채택하지 않은 안

**묻되 `confirmDialog`로 옮기기.** 세 확인 흐름의 컴포넌트가 통일되지만, ②의 문제 —
드문 실패를 잡으려고 흔한 성공에 모달을 세우는 구조 — 를 전혀 풀지 않는다.

**아예 묻지 않고 배지 문구를 정직하게 바꾸기.** `lastExportedAt`을 무조건 갱신하고 배지를
"마지막 **내보내기** 30일 전"으로 읽는다. 코드가 가장 줄고 물음이 0개다. 하지만 저장 시트를
취소해도 배지가 지워지고, **그 시나리오가 이 앱이 겪을 수 있는 유일한 재앙**(30일 방치 →
아이패드 사망 → 전량 소실)이라 채택하지 않았다. 되돌리기 토스트는 같은 "묻지 않음"을
얻으면서 정정 경로를 남긴다.

## 범위

| 파일                    | 변경                                                                                           |
| ----------------------- | ---------------------------------------------------------------------------------------------- |
| `src/ui.ts`             | `toast()`에 `action`·`durationMs` 옵션 추가                                                    |
| `src/screens/report.ts` | 내보내기 확인 배너 → 되돌리기 토스트, 초기화 확인 배너 → `confirmDialog`, `#confirm` 기반 삭제 |

### `toast()` 확장 (`src/ui.ts`)

```ts
export function toast(
  message: string,
  opts: {
    tone?: 'neutral' | 'positive'
    action?: { label: string; onClick: () => void }
    durationMs?: number
  } = {},
): void
```

SEED snackbar 레시피에 필요한 슬롯이 이미 다 있다(설치본 `snackbar.d.ts` 확인:
`root`·`message`·`prefixIcon`·`actionButton`·`content`). 새로 그릴 CSS가 없다.

- **`action`이 있을 때만** `seed-snackbar__content`로 감싸고
  `<button class="seed-snackbar__actionButton">`을 형제로 붙인다. `.seed-snackbar__root`가
  `display:flex; align-items:center`이고 `__content`가 `flex-grow:1; justify-content:space-between`
  이라(설치본 `snackbar.layered.css` 확인), 감싸는 것만으로 메시지와 버튼이 양끝으로 갈린다.
  `__actionButton`은 `:after`로 44px 히트 영역을 확보해 두어 아이패드 터치에도 맞다.
- **`action`이 없으면 지금 DOM 그대로** — `__message`가 `root`의 직계 자식으로 남는다.
  `__content`는 `padding-inline`을 더하므로 전부 감싸면 기존 토스트가 미세하게 움직인다.
  요청 범위 밖의 시각 변화를 만들지 않기 위해 조건부로 둔다.
- `durationMs` 기본값은 3000 — 브리프의 노출 3초 계약을 그대로 유지한다. 되돌리기 토스트만
  8000을 넘긴다. 노출이 끝나면 `data-open`을 떼고 100ms(`--seed-duration-d2`) 뒤 실제 제거하는
  기존 exit 처리는 손대지 않는다.
- 액션 클릭은 `settled` 플래그로 **한 번만** 실행된다(`confirmDialog`의 `settle`과 같은
  이중탭 방어). 실행 즉시 토스트를 닫고, 예약된 타이머가 뒤늦게 또 닫지 않도록
  `clearTimeout`한다.
- **`hashchange`에 반응하지 않는다.** `confirmDialog`는 해시가 바뀌면 스스로 취소로 닫히는데
  (이전 화면 맥락의 작업을 뒤늦게 확정시키지 않기 위해서다), 토스트 액션은 성질이 다르다 —
  되돌리기는 어느 화면에서 눌리든 항상 올바른 연산이고, 오히려 화면을 옮겼다고 되돌릴
  기회를 뺏는 쪽이 손해다.

### 내보내기 흐름 (`src/screens/report.ts`)

```
#export 클릭
  → triggerDownload (실패하면 showError 후 종료 — 여기는 그대로)
  → prev = meta.settings.lastExportedAt  (되돌릴 값. string | null)
  → putMeta(lastExportedAt = now)
      성공 → toast('백업했어요', { tone:'positive', durationMs:8000,
                                  action:{ label:'저장 안 했어요', onClick: revert } })
             + 해시가 그대로면 renderReport(root)  // 30일 배지 갱신
      실패 → showError('백업 기록을 남기지 못했어요.', e)
              (파일은 이미 내려갔다 — 이 실패는 기록 실패지 백업 실패가 아니다)
```

되돌리기는 **읽고-고쳐-쓰기**로 한다:

```ts
getMeta().then((cur) => putMeta({ ...cur, settings: { ...cur.settings, lastExportedAt: prev } }))
```

렌더 시점에 읽은 `meta`를 8초 뒤에 그대로 되쓰면 그 사이 초기화(`resetAll`)가 끝난 경우
방금 지운 상태 위에 낡은 meta를 덮는다. `importBusy`/`resetBusy`는 가져오기와 초기화가
서로를 막게 할 뿐 내보내기는 막지 않으므로 실재하는 경합이다. 되돌리기 시점에 다시 읽으면
사라진다.

`prev`는 `string | null`이다(`types.ts:138`). `undefined`로 되돌리면 `validateBackup`이
거부하므로(`backup.ts:116`) **반드시 `null`을 쓴다** — 한 번도 백업한 적 없는 상태로
되돌리는 경우가 여기 해당한다.

되돌리기 성공 시 `백업 기록을 되돌렸어요` 토스트(액션 없음)를 띄우고, 해시가 그대로면
`renderReport(root)`로 배지를 되살린다.

### 초기화 확인 (`src/screens/report.ts`)

`confirmDialog`로 옮긴다.

| 항목           | 값                                                                      |
| -------------- | ----------------------------------------------------------------------- |
| `title`        | `모든 기록을 지울까요?`                                                 |
| `description`  | 4줄 배열 — 기록 범위 / 되돌릴 수 없음 / 미채점 경고(조건부) / 백업 경과 |
| `confirmLabel` | `네, 지울게요`                                                          |
| `cancelLabel`  | `취소`                                                                  |
| `tone`         | `critical`                                                              |

- **`range`의 `escapeHtml`을 뺀다.** `confirmDialog`는 모든 줄을 `textContent`로 넣으므로
  (`ui.ts:145-155`) 이스케이프하면 `&amp;` 같은 문자열이 글자 그대로 보인다. 가져오기 쪽이
  이미 같은 이유로 이스케이프 없이 넘기고 있다(그쪽 주석 참고).
- `<strong>되돌릴 수 없어요.</strong>`의 굵게가 사라진다 — `textContent` 전용이라 어쩔 수
  없고, `tone: 'critical'`과 독립된 한 줄 배치가 그 자리를 대신한다.
- `yes.disabled` 이중탭 가드를 제거한다. `confirmDialog`의 `settle`이 정확히 한 번만
  resolve하므로 중복이다.
- 취소·배경 클릭·Esc·해시 변경은 전부 `confirmDialog`가 `false`로 모아 주므로,
  `if (!ok) { setResetBusy(false); return }` 한 줄이 기존 `#reset-cancel` 핸들러를 대체한다.

### 삭제되는 것

`#confirm` div, `confirmEl`, `showConfirmPanel`, `clearConfirmPanel`, `confirmCleanup`,
`resetPanelCleanup`, 그리고 현재 202-225행의 겹침 정리 주석 블록.

이 기반은 "내보내기 확인과 초기화 확인이 같은 컨테이너를 공유하다가 한쪽이 다른 쪽을
덮으면 덮인 패널의 상태(`resetBusy`)를 풀 버튼이 사라져 잠금이 고착된다"는 결함을 막으려고
만든 것이다. 두 사용처가 모두 사라지면 공유 컨테이너 자체가 없어지므로 결함의 전제가
소멸한다 — `confirmDialog`는 각자 자기 오버레이를 갖고 `settle`이 자기 정리를 하므로 겹침
정리라는 개념이 필요 없다.

`escapeHtml` import는 남는다 — `report.ts`의 다른 두 곳(81·97행)이 계속 쓴다.

## 하지 않는 것

- **`importBusy`/`resetBusy` 구조를 손대지 않는다.** 내보내기는 이 가드에 참여하지 않았고
  이번에도 참여시키지 않는다 — 내보내기는 읽기 + `Settings` 한 필드 쓰기라 `days`를 건드리는
  두 파괴적 작업과 성격이 다르다. 초기화와의 경합은 되돌리기의 읽고-고쳐-쓰기가 해소한다.
- **`triggerDownload`를 손대지 않는다.** 다운로드 트리거 자체는 그대로다.
- **가져오기(복구) 흐름을 손대지 않는다.** 이미 `confirmDialog`를 쓴다.
- **30일 배지의 기준·문구를 바꾸지 않는다.** `weeklyReport`의 `exportOverdue` 계산은 엔진에
  있고 이 설계가 닿지 않는다.
- **테스트를 추가하지 않는다.** `engine/` 순수 함수가 바뀌지 않는다(설계 §12). 화면·DOM
  테스트는 이 레포에 없다.

## 감수하는 위험

토스트를 보지 못하고 넘기면(다른 곳을 보고 있었거나 8초를 놓쳤거나) 배지가 "백업됨"으로
거짓말한다. 수명은 다음 30일 주기까지다.

지금 방식(묻기)은 이걸 막지만 그 대가로 흔한 성공 경로에 매번 탭을 물린다. 그 교환을
의도적으로 뒤집는 설계다 — 근거는 ②에 있다. 실제로 배지가 어긋나는 일이 반복되면
"되돌리기 토스트를 놓쳤을 때 다음 리포트 방문에서 한 번 더 확인" 같은 후속을 검토한다.

## 불변식 확인

- **소속 분리:** 전부 `#/report`(부모 소속) 내부다. 새 `navigate()`가 없고 기존 목적지도
  안 바뀐다
- **`derived` 비배선:** `lastExportedAt`은 로그에서 재계산되는 파생값이 아니라 `Settings`
  필드다. 소급 재해석 규칙과 무관하다
- **XSS 경계:** 변경 방향이 안전한 쪽이다 — `el()` 템플릿 보간(`range`, 일수)이 사라지고
  `confirmDialog`의 `textContent`로 옮겨간다. `escapeHtml` 제거는 그 이동의 결과이지
  이스케이프를 빠뜨리는 것이 아니다
- **재인쇄 동일성·단일 출처:** 이 설계가 닿지 않는다. 새 색·크기 값을 CSS에 베끼지 않고
  SEED 레시피 클래스만 쓴다
- **문서 포맷:** `docs/` 커밋 전 `npm run format`(CI의 `prettier --check .`가 마크다운까지 본다)

`npx prettier --check .` · `npm test` · `npm run build`.

   「가져오기」 버튼이 다시 활성인지
6. 다이얼로그의 날짜 범위에 `&amp;` 같은 문자열이 보이지 않는지
