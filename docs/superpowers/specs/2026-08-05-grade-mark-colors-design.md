# 채점 표시의 색 — 검정+빨강에서 회색+주황으로

**날짜:** 2026-08-05 **상태:** 승인됨(사용자), 구현 대기

채점 화면의 O/X 버튼에서 근사 검정(`neutralSolid`)과 채도 높은 빨강(`criticalSolid`)을
걷어내고, 연회색(`neutralWeak`)과 앱의 강조색인 당근 주황(`brandSolid`)으로 바꾼다.

## 왜 — 두 겹의 이유

### ① 전제가 무너졌다

`grade.ts`의 현재 주석은 빨강을 이렇게 정당화한다:

> O는 neutral, X는 critical이다 — 채점 화면은 부모 소속이라 빨강이 아이에게 부담을
> 주지 않고, 부모가 훑을 때 오답이 즉시 눈에 띄는 편이 이득이다(설계 §5).

빨강이 허용된 근거는 **"아이가 이 화면을 안 본다"** 하나뿐이다. 그런데 리뷰 P3-2는
함께 채점하는지를 "실사용 확인 후 결정"으로 미뤄뒀고, **2026-08-05 사용자 확인 결과
"때따라 다르다"**였다. 아이가 보는 날이 있다면 안전한 기본 가정은 "볼 수 있다"이고,
그러면 `brand.md` §3의 약속이 이 화면에도 걸린다:

> **틀림은 벌이 아니다** — 오답은 판정이 아니라 다음 연습의 재료다.
> 집행: 오답 reveal + 재투입, **아이 화면 빨강 금지**, 타이머 비표시

같은 표 아래 문장이 우선순위를 정해 준다 — _"새 기능·새 문구가 이 표의 어느 약속과
충돌하면, 기능이 아니라 약속이 이긴다."_

### ② 팔레트에 없는 색이다

앱이 실제로 쓰는 채도 있는 색은 **주황(`bg-brand-solid`, 6회)과 초록
(`bg-positive-solid`, 2회)** 둘뿐이고, 빨강은 「모든 기록 지우기」의 **글자색으로 1회**
(`fg-critical`)가 전부다. 나머지는 흰 카드·gray-400 실선·중립 글자다.

채점 화면은 **앱에서 유일하게 무거운 solid 덩어리**를 쓰면서 하필 그 두 강조색 중
어느 것도 아닌 조합(gray-900 근사 검정 + 채도 높은 빨강)을 쓴다. "톤에 안 어울린다"는
관찰(사용자, 2026-08-05)의 출처가 여기다.

### 덤 — 강조가 뒤집혀 있었다

기본 상태(맞음)가 가장 무겁게 그려져서, 잘 푼 날일수록 화면이 검은 블록 기둥이 됐다.
바꾸면 조용한 화면에 틀린 것만 뜬다.

## 무엇을

| 상태         | 지금                   | 바뀐 뒤             |
| ------------ | ---------------------- | ------------------- |
| 맞음(기본값) | `neutralSolid` + `⭕`  | `neutralWeak` + `○` |
| 틀림         | `criticalSolid` + `❌` | `brandSolid` + `✕`  |

**이모지를 텍스트 글리프로 바꾸는 것이 필수다.** `⭕`(U+2B55)와 `❌`(U+274C)는 자체
색을 가진 이모지라 CSS `color`가 듣지 않는다 — 배경만 바꾸면 연회색 칸 위에 빨간
동그라미가 그대로 남는다.

의미는 글리프가 지고 색은 주목만 담당한다. 주황은 "여기 봐"이지 "틀렸어"가 아니다 —
원래 의도였던 *"부모가 훑을 때 오답이 즉시 눈에 띈다"*는 그대로 유지된다.

대비는 확보돼 있다: `.grade-row`는 흰 카드(`bg-layer-default`)라 그 위의 연회색
(gray-200) 칸은 구분되고, 주황 위 흰 `✕`는 SEED 레시피가 `fg-neutral-inverted`를 준다.

## 하지 않는 것

- **CSS를 건드리지 않는다.** `.mark`는 폭(52px)만 정하고 색·배경·높이·radius는 전부
  SEED variant가 준다. variant 클래스 이름만 바꾸면 끝난다
- **스크린리더 라벨을 추가하지 않는다.** 지금도 없어 글리프만 읽히지만, 이번 불만과
  무관하고 아이패드 터치 전용이다. 후속으로 남긴다
- **초록(`positive`)을 맞음에 쓰지 않는다.** 이 앱에서 초록은 이미 "완료"(✅ 완료일수,
  `.step.done`)의 뜻이라 "정답"으로 겹쳐 쓰면 어휘가 흐려진다
- **브랜드 색이 미정인 것은 문제가 아니다.** `brand.md` §7이 브랜드 색을 미정으로
  두지만, 우리는 값이 아니라 토큰(`bg-brand-solid`)을 가리키므로 나중에 색이 정해지면
  이 버튼도 자동으로 따라간다. 이건 의도된 동작이다

## 범위

| 파일                                  | 변경                                                                                  |
| ------------------------------------- | ------------------------------------------------------------------------------------- |
| `src/screens/grade.ts`                | 초기 마크업의 variant·글리프, `paint()`의 variant 스왑·글리프, 그리고 **뒤집힌 주석** |
| `docs/design/brand.md`                | §3 "아이 화면 빨강 금지"가 채점 화면까지 포함함을 밝힌다                              |
| `docs/design/ux-review-2026-08-05.md` | 결정 기록에 P3-2의 답("때따라 다르다")과 그 귀결을 남긴다                             |

주석을 반드시 고친다 — 지금 주석은 이 변경과 정반대를 주장하므로, 두면 다음 사람이
근거를 읽고 되돌린다.

## 불변식 확인

- **소속 분리:** `navigate()` 변화 없음
- **XSS 경계:** 새 보간이 없다. 글리프는 우리가 쓰는 리터럴이고 기존 `escapeHtml`는 유지
- **단일 출처:** SEED 토큰을 값으로 베끼지 않는다 — variant 클래스만 쓴다
- **재인쇄 동일성·`derived` 비배선:** 닿지 않는다
- **테스트:** 화면 변경이라 추가하지 않는다(설계 §12). **303 유지**

## 검증

`npx prettier --check .` · `npm test`(303) · `npm run build`.

사람 확인(DOM 테스트가 없다):

1. 맞음 칸이 흰 카드 위에서 버튼으로 보이는지(너무 옅어 사라지지 않는지)
2. 틀림의 주황 위 `✕`가 선명한지
3. 14행을 훑을 때 틀린 것이 즉시 눈에 띄는지 — 원래 의도가 유지됐는지
4. `○`/`✕` 글리프 크기가 이모지 때와 비슷하게 읽히는지(폰트에 따라 작아 보일 수 있다)
