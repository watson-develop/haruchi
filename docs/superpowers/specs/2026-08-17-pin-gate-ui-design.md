# PIN 게이트 UI 교체 — 키패드 스타일

2026-08-17. 2B 스펙(`2026-08-12-sync-phase2b-pin-design.md`)이 세운 게이트의 **껍데기만**
바꾼다. 당근페이 비밀번호 화면을 참조 모델로: 풀스크린, 도트 인디케이터, 터치 키패드,
자동 판정. 게이트의 의미(언제 뜨나·무엇을 지키나·틀리면 어떻게 되나)는 바뀌지 않는다 —
바뀌는 것은 `ui.ts` `unlockGate()` 내부 DOM, `app.css`의 스타일, 그리고 낡아지는 문서
한 곳(`supabase/README.md`)이다.

적대적 리뷰 2라운드(2026-08-17, 발견 8+7건)가 반영돼 있다 — §2의 짐 세 개(z-index·
safe-area·touch-action)와 300ms 탭 실드, §3 델타 표, §4의 소급 확인, §6의 README와
검증 절차. touch-action 재시도는 사용자 결정(revert 사유 미기록 — §2).

## §1 유지되는 계약

2B 스펙과 현재 구현이 세운 계약 중 이 작업이 그대로 지키는 것. 이 표는 리뷰
체크리스트다 — 구현 diff에서 아래 항목이 하나라도 움직였으면 그 diff는 틀렸다.
(2B에서 **달라지는** 것은 §3의 델타 표에 따로 있다 — 여기 섞지 않는다.)

| 계약                                                      | 근거                                           |
| --------------------------------------------------------- | ---------------------------------------------- |
| 시그니처 `unlockGate(expected: string): Promise<boolean>` | 호출자 main.ts 무변경                          |
| 단일 비행 — 떠 있으면 같은 Promise                        | route(false) 겹침이 다이얼로그를 쌓는다(2B §4) |
| settle 정확히 1회, 어느 경로로 닫혀도                     | confirmDialog와 같은 오버레이 규약             |
| hashchange → 취소                                         | #app 밖에 사는 것은 수명을 스스로 관리         |
| Escape → 취소                                             | 기존 동작 유지                                 |
| 통과 시 `gatePassed = true`, `lockGate()`가 지움          | 포그라운드 세션 플래그(2B §4)                  |
| 틀린 입력은 닫지 않는다 — 비우고 안내만 바꾼다            | 잠금·지연 없음(위협 모델: 여덟 살)             |
| 입력값 평문은 어디에도 렌더되지 않는다                    | 마스킹 input이 도트로 바뀔 뿐, 노출 없음 유지  |
| `.overlay` 클래스                                         | 인쇄에서 숨는 유일한 표식(print.css)           |
| `document.body` 부착                                      | #app 교체(replaceChildren)로 사라지지 않아야   |
| main.ts·db.ts·sync.ts 무변경                              | 게이트 위치·판정·캐시는 이 작업의 범위 밖      |
| 모달 의미 보존: `aria-modal="true"` + 초기 포커스         | 현재 alertdialog가 주던 것 — 후퇴 금지         |

## §2 모양

풀스크린 오버레이 하나. SEED 다이얼로그 클래스(`seed-dialog__*`)를 버리고 전용 클래스
(`pin-gate` 계열)로 간다 — 다이얼로그 레시피는 카드+백드롭 모양이라 풀스크린과 싸우고,
이기려고 덮어쓰기 시작하면 레이어 전략의 shorthand 함정(CLAUDE.md)을 밟는다. 색·타이포는
SEED 토큰(`var(--seed-*)`)을 가리킨다 — 값 복사 금지(단일 출처 규칙).

```
┌────────────────────────┐
│ ✕                      │  좌상단 취소 버튼 (aria-label="닫기")
│                        │
│       부모 확인         │  제목
│  비밀번호를 입력하세요    │  부제 — 틀리면 "다시 입력해 주세요"로 교체
│                        │
│      ● ● ● ○           │  도트 expected.length개, 입력 자리만큼 채움
│                        │
│      1   2   3         │
│      4   5   6         │  고정 배치 키패드 (랜덤 아님 — 사용자 결정)
│      7   8   9         │
│    취소  0   ←         │  취소 = settle(false), ← = 마지막 한 자리 지움
└────────────────────────┘
```

- **자동 판정**: 입력 길이가 `expected.length`에 닿는 순간 `===` 비교. 맞으면
  `settle(true)`, 틀리면 입력을 비우고(도트 전부 빈 원) 부제 교체. 확인 버튼 없음
- **탭 관통 방지**: `settle(true)` 시 키패드 버튼을 즉시 disable하고 오버레이 제거는
  **300ms** 늦춘다(iOS 더블탭 인식 창 상한 — 한 프레임으로는 두 번째 탭이 도착하기 전에
  오버레이가 이미 없다). 그동안 오버레이가 두 번째 탭을 삼켜, 아래에 렌더되는 화면
  (#/grade의 O/X 토글)에 떨어지는 것을 막는다. resolve는 즉시다 — 늦추는 것은 DOM 제거뿐.
  settled 가드가 이미 있으므로 「정확히 1회」 규약과 충돌하지 않는다
- **도트 개수 = `expected.length`**: PIN 길이가 화면에 드러난다. 감수 — 위협이 여덟 살이고
  참조 모델(당근페이)도 6개를 고정 노출한다. 도트 컨테이너는 `flex-wrap: wrap` — SQL로
  긴 PIN(전화번호 습관)을 넣어도 화면 폭을 넘지 않는다
- **키패드 클래스는 `.pin-gate-keypad` 전용** — 스프린트의 `.keypad`를 공유하지 않는다.
  그쪽 크기 결정(max-width·64px 버튼)은 여덟 살 손가락 기준으로 고른 값이라, 공유하면
  아이 화면의 치수 조정이 부모 게이트를 조용히 함께 움직인다. 모양이 닮은 것은 우연이고
  주인이 다르다
- **물리 키보드**: `0`–`9` 입력, `Backspace` 지움, `Escape` 취소. document keydown
  리스너(기존 자리) — input이 없으므로 소프트 키보드는 뜨지 않는다(의도)
- **취소 경로 셋**: ✕ 버튼, 키패드 `취소`, Escape — 전부 `settle(false)`. 백드롭 클릭
  취소는 사라진다(풀스크린이라 백드롭이 없다 — §3 델타 표)

**SEED 다이얼로그 클래스가 지던 짐 셋 — 전용 클래스가 인수한다** (리뷰 1라운드 발견
1·2·3. 셋 다 CSS 몇 줄이고, 빠지면 각각 실기기에서 실제로 깨진다):

- **z-index**: `.pin-gate { z-index: 100 }` — 다이얼로그가 쓰던 `--dialog-z-index: 100`과
  같은 층. 이게 없으면 `.update` 배너(z-index 10, position:fixed)가 PIN 화면 **위에**
  떠서 게이트 도중 업데이트 버튼이 뚫려 보인다. 이 함정은 다이얼로그 도입 때 이미 한 번
  밟았다(app.css의 "다이얼로그가 배너 뒤로 숨는다" 주석)
- **safe-area**: `index.html`에 `viewport-fit=cover`가 실재하므로 풀스크린 `inset:0`은
  상태바·홈 인디케이터 밑까지 깔린다. `.pin-gate`에
  `padding: env(safe-area-inset-top) env(safe-area-inset-right) env(safe-area-inset-bottom) env(safe-area-inset-left)`
  — 없으면 좌상단 ✕가 상태바에 깔리고 하단 키 줄이 홈 인디케이터와 겹친다(standalone
  PWA가 이 앱의 주 사용 형태)
- **touch-action**: `.pin-gate { touch-action: manipulation }` — 좁은 중앙 블록에서 iOS
  더블탭 확대가 튀는 것은 이 레포가 실측한 기지 결함이고(커밋 24fe4b0, 전역 수정은
  80a2910로 revert돼 현재 트리에 없다), 반복 숫자 PIN('1122'·'7777')은 같은 키
  더블탭이 확정이다. **revert 사유는 기록에 없다**(커밋 본문 없음, HANDOFF 해당 절도
  함께 삭제됨) — 사용자 결정(2026-08-17): 스코프를 `.pin-gate`로 좁혀 재시도한다.
  전역 재발이 아니라 이 오버레이 안에서만 유효하므로, revert를 부른 증상이 무엇이었든
  노출면이 게이트 화면 하나로 준다. 실기기 검증(§6의 4)이 재발 감시를 겸한다

**접근성** (리뷰 발견 6 — 현재 alertdialog가 주던 것을 후퇴시키지 않는다):

- `.pin-gate` 루트에 `role="alertdialog"` + `aria-modal="true"` — 현행 role 그대로
- 루트에 `tabindex="-1"` 주고 열릴 때 포커스 — 기존 `input.focus()`의 대체
- 부제(안내 문구)에 `aria-live="polite"`. 오답 시 부제는 비운 뒤 **다음 틱에서**
  (setTimeout) 다시 넣는다 — 같은 틱의 두 변경은 브라우저가 병합해 라이브 리전이 침묵할
  수 있고, 그러면 연속 오답 2회째의 같은 문자열 재설정이 공지되지 않는다
- 키패드 키는 `<button>` — 도트는 장식(`aria-hidden="true"`). 입력 진행(몇 자리째)은
  시각 전용으로 감수한다 — 자리마다 낭독하는 것은 옆의 아이에게 자리수를 세어 주는
  것이기도 하다

## §3 2B에서 달라지는 것 (델타 표)

2B §7과 같은 형식. **사용자 상호작용 계약**의 델타는 아래 다섯 줄이 전부다 — §2가 새로
넣는 300ms 탭 실드와 게이트 내 `touch-action`도 관찰 가능한 변화지만, 그 둘의 명세는
§2가 주인이라 여기 겹쳐 적지 않는다.

| 2B·현재 구현                   | 이 스펙                                   | 근거                                     |
| ------------------------------ | ----------------------------------------- | ---------------------------------------- |
| `type="password"` 마스킹 input | input 없음 — 도트 인디케이터              | 참조 모델. 평문 비노출은 동일하게 유지   |
| `maxlength="4"` (UI 제약)      | 없음 — 도트·판정이 서버 PIN 길이를 따라감 | 길이를 클라이언트가 이중 정의하지 않는다 |
| Enter → submit                 | 삭제 — 자동 판정이라 submit 자체가 없다   | 확인 버튼과 함께 사라진다                |
| 백드롭(positioner) 클릭 → 취소 | 삭제 — 풀스크린이라 백드롭이 없다         | 취소는 ✕·키패드 취소·Escape 셋           |
| 부제 "PIN을 입력해 주세요"     | "비밀번호를 입력하세요"                   | 참조 모델 문구. 제목 "부모 확인"은 유지  |

## §4 숫자 전용 PIN — 새로 명시되는 계약

키패드는 숫자만 넣을 수 있다. 서버 `app_config.pin`은 text라 SQL로 `'abcd'`를 넣을 수
있고, 그러면 **어느 기기도 게이트를 못 연다**(입력 수단이 없다 — 잠기는 쪽에 파괴적 작업
화면 #/manage가 포함된다). 코드 가드는 안 만든다 — PIN을 넣는 사람과 잠기는 사람이 같은
아빠 한 명이고, 2B §5가 이미 SQL을 "사람이 지키는 경로"로 정의했다. 대신 두 가지를 한다:

- **계약 명시**: PIN은 숫자로만 구성한다. `supabase/README.md`의 PIN 절에 적는다(§6)
- **소급 확인**: 현재 구현은 `inputmode="numeric"`이 힌트일 뿐이라 외장 키보드로 숫자
  아닌 PIN을 이미 넣었을 수 있다 — 배포 전 `select pin from app_config`로 지금 서버 값이
  숫자 전용인지 확인한다(§6 검증 절차)

빈 문자열 PIN(`pin=''`)은 이 화면에 도달하지 않는다 — pullConfig가 `''`를 「PIN 없음」으로
읽어 캐시를 `null`로 지우고(2B §3), `null`이면 main.ts가 `unlockGate`를 부르지 않는다.

## §5 뺀 것

- **생체인증** — PWA에 OS 지갑 연동이 없고, WebAuthn은 위협 모델(여덟 살의 우연한 접근,
  평문 PIN, 잠금 없음)에 과잉이다
- **"비밀번호를 모르겠어요" 링크** — 복구가 설계상 SQL 전용(2B §5)이라 링크가 갈 곳이
  없다. 잊으면 SQL로 바꾼다 — 오늘과 같다
- **랜덤 키패드 배치** — 사용자 결정(2026-08-17): 고정 배치. 근육 기억으로 빠르게 입력
- **잠금·지연·시도 횟수 제한** — 2B 위협 모델 그대로

## §6 파일과 검증

- `src/ui.ts` — `unlockGate()` 내부 교체. 모듈의 다른 export는 무변경
- `src/styles/app.css` — `pin-gate` 계열 스타일 추가(§2의 짐 셋 포함)
- `supabase/README.md` — PIN 절 갱신: "4자리 숫자 키패드·4자리 초과는 안 열린다"는 서술이
  낡는다(maxlength 폐지) → "숫자만, 길이 자유(도트가 길이를 따라감)"로 교체하고 숫자 전용
  계약(§4)을 명시
- 테스트 없음 — DOM 화면은 테스트하지 않는다(기본 설계 §12). 판정은 `===` 비교 하나라
  엔진으로 추출할 로직이 없다
- 검증 절차:
  1. 배포 전 `select pin from app_config` — 숫자 전용인지 확인(§4 소급 확인)
  2. `npx prettier --check .` · `npm test`(기존 전체) · `npm run build`
  3. dev 서버 육안: localhost origin은 보통 미등록이라 pull이 안 돌고(`syncEnabled()`의
     `deviceKey !== null` 검사 — origin 격리 때문이 아니다) PIN 캐시가 저절로 생기지
     않는다. devtools **콘솔에서** `device` 스토어의 `'current'` 레코드를 **읽어 `pin`만
     바꿔 되쓴다** — 단일 레코드에 DeviceState 전체가 앉아 있어 `{pin}`만 put하면 나머지
     필드(`deviceId` 등)가 날아간다. 되쓰기 전에 그 레코드의 `deviceKey`가 null인지 확인
     — null이 아니면 이 origin이 등록돼 있어 pull이 주입값을 서버 값으로 덮는다. 게이트는
     네트워크를 안 만지고 캐시만 읽으므로 주입으로 충분하다(2B §4). 그 뒤 `#/grade` 진입 —
     게이트 모양, 오답 후 안내 교체, ✕·취소·Escape 세 경로, 통과 후 채점 화면
  4. 실기기(아이패드 standalone): safe-area(✕·하단 키 줄), 같은 키 빠른 연타에 확대 안
     튀는지, 업데이트 배너가 떠 있을 때 게이트가 위를 덮는지, **그리고 touch-action 재시도가
     과거 revert(80a2910)를 부른 증상을 게이트 화면 안에서 재현하지 않는지** — 스크롤·탭
     반응이 이상하면 이 한 줄이 용의자다
