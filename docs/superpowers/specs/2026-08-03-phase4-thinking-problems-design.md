# Phase 4 — 생각하는 문제 (전략 존 + 문장제) + 구구단 풀 개편

작성: 2026-08-03. 전제: Phase 1·2·3 완료(테스트 185개), 배포 완료. 원 설계 §6.4·§6.5·§6.6이 정의한 "2장 — 생각하는 문제"를 채우고, 사용자 결정으로 구구단 풀을 개편한다.

**한 줄 목표**: 세로셈만 훈련한 아이는 막히면 길이 하나뿐이다 — 방법(전략)과 번역(문장제)을 종이 2장째로 더한다.

## 0. 결정 경위 (브레인스토밍 합의)

| 질문              | 결정                                                                       |
| ----------------- | -------------------------------------------------------------------------- |
| 범위              | **전략 존 + 문장제 둘 다** 한 Phase에                                      |
| 인쇄 구조         | **단면 2장** (설계 원문 §6.6) — 1장 계산, 2장 생각하는 문제                |

2학년 교육과정 리뷰(2026-08-04)가 다섯 곳을 더 다듬었다: ⑤ `double`의 두 배 step을 덧셈 표기로 — 두 자리 × 한 자리는 3-1([4수01-04]) ⑥ 도입이 끝나거나 막히면 문항1도 로테이션(정착기 규칙 — 없으면 문항1이 마지막 전략에 영구 고정) ⑦ `count-up`은 근접 쌍만 생성(차 3\~15, 십의 경계 통과) ⑧ 전략 피연산자·결과를 두 자리로 제한 — **제안됐다가 같은 날 철회**(§3, 구현 없음) ⑨ 같은 수식 재사용은 같은 연산일 때만.

## 1. 전체 구조

Phase 4는 두 덩어리다.

```

  engine/facts.ts        FACT_IDS = 2×1~9×9 (72식). DAN_ORDER 폐기 — 신규 도입은 rand로 무작위
  screens/fact-map.ts    지도 8행(2~9단)×9열(×1~×9), "N / 72"
  screens/report.ts      "구구단 N/72" 문구
  engine/simulation.test 실측 기준값 재유도 (81→72, 바닥값·굶주림 상한)

② 생각하는 문제
  engine/strategy.ts     전략 8종 카탈로그 + 생성 + steps + 도입/로테이션   (새 파일)
  engine/word.ts         문장제 템플릿 + 조사 처리 + 이름 슬롯              (새 파일)

  engine/compose.ts      전략 2 + 문장제 2 조립. 시그니처 {settings, types, strategies, facts, rand}
  screens/print-sheet.ts 2페이지 렌더(page-break) + 전략 존·문장제 레이아웃
  screens/grade.ts       새 문항 종류의 번호·라벨·정답 표시
  engine/report.ts       주간 리포트에 "배운 방법 N/8" + 전략 정답률 행
```

**기존 불변식을 전부 그대로 탄다.**

- **마이그레이션 없음** — `StrategyItem`·`WordItem`·`StrategyStep`·`StrategyState`·`Derived.strategies`가 Phase 1 types에 이미 있다. `Day`에 새 필수 필드 없음
- **재인쇄는 같은 문제** — 전략·문장제도 생성 시점에 `sheet`에 못박고 재인쇄는 렌더만
- **상태는 전부 파생** — `deriveStrategies`는 로그 재생이고 저장하지 않는다. `Meta.derived`는 계속 아무도 읽지 않는다
- **빈 sheet 규칙** — 스프린트만 한 날(`sheet: []`)은 전략 파생에서도 건너뛴다

`composeSheet` 호출부는 `print-sheet.ts`와 테스트뿐이고, `print-sheet.ts`는 이미 `getAllDays()`를 부르고 있어 파생 입력 추가 비용이 없다.

## 2. 구구단 풀 개편

- **풀**: `FACT_IDS` = `2×1` ~ `9×9` (a ∈ 2..9, b ∈ 1..9, 72식). 0단·1단을 뺐던 이유(규칙이 하나뿐이라 인출 훈련 대상이 아님)를 1단에도 적용하되, 곱하는 수 ×1은 남긴다 — 외우는 구구단이 2×1부터라서다(사용자 결정). 1단·0의 곱은 2-2 곱셈구구 단원(학교·EBS)에는 있으므로, `facts.ts` 주석에 "1단·0은 학교 몫"이라는 역할 분담도 함께 기록한다
- **도입 순서 폐기**: `DAN_ORDER`·`FACT_ORDER`를 없애고, `composeSprint`의 신규 식 선택을 주입된 `rand`로 섞는다. 교육청 지도서 순서를 버리는 것은 **사용자 결정**이며 `facts.ts` 주석에 그렇게 기록한다. 결정성은 유지된다 — 그날 큐는 여전히 생성 시점에 `sheet`/세션에 고정
- **기존 1단 기록은 조용히 무시된다** — `deriveFacts`가 모르는 id를 건너뛰는 것이 원래 설계라 마이그레이션이 필요 없다. 실기기 로그는 사실상 비어 있어(2026-08-03 기준 하루치, 스프린트 없음) 실손실 없음
- `factAnswer`의 형식 정규식(`[1-9]×[1-9]`)은 풀보다 넓지만 그대로 둔다 — 이 함수의 입력은 엔진이 방금 만든 큐뿐이고, 정규식은 형식 모순 검출용이지 풀 검증용이 아니다(기존 비대칭 원칙)
- **지도**: 8행(2단부터 9단) × 9열(×1부터 ×9) 직사각형. `factMapHtml`의 하드코딩된 1..9 루프를 풀 상수에서 유도한다. 점수 표기 "N / 72". 교환법칙 대각 대칭은 2×2~9×9 영역에서 그대로 보인다
- 점검(`CHECKUP_MIN_FLUENT` 10)·간격 사다리·유창 판정·스트릭은 풀 크기와 무관 — 무변경

## 3. 전략 엔진 (`engine/strategy.ts`)

### 카탈로그가 곧 코드다

```ts
type StrategyDef = {
  id: StrategyId // types.ts의 8종 유니온
  op: '+' | '−' | '×'
  name: string // 인쇄·채점 라벨: "10 만들어 더하기"
  gen(rand): { a: number; b: number } // 이 전략이 "강한" 수 조합을 기각 표집으로 생성
  applicable(a, b): boolean // 다른 문항의 수식을 재사용할 수 있는지
  steps(a, b): StrategyStep[] // 빈칸 뼈대 — 마지막 step의 빈칸이 최종 답
}
```

렌더러는 `steps`만 알고 전략을 모른다(원문 "렌더러는 하나"). `answer`는 마지막 step의 빈칸 값이며 채점은 그것 하나만 O/X한다.

### 카탈로그 8종 (원문 §6.4 표 기반, 예시 3건은 교육과정 리뷰로 교체)

| id                 | 연산 | 이름               | 강한 조건             | steps 예                                 |
| ------------------ | ---- | ------------------ | --------------------- | ---------------------------------------- |
| `make-ten`         | +    | 10 만들어 더하기   | —                     | `27+3={30}` → `30+12={42}`               |
| `split-place`      | −    | 자리로 나누어 빼기 | 받아내림 **없을 때**  | `60−20={40}` → `8−5={3}` → 합치면 `{43}` |
| `round-adjust`     | +    | 어림하고 고치기    | 더하는 수가 애매할 때 | `27+20={47}` → `47−1={46}`               |
| `split-subtrahend` | −    | 빼는 수 가르기     | **언제나 안전**       | `63−20={43}` → `43−8={35}`               |
| `anchor`           | −    | 기준수 만들어 빼기 | 빼는 수가 9·19류      | `52−20={32}` → `32+1={33}`               |
| `count-up`         | −    | 채워 세기          | 두 수가 가까울 때     | `58→60 {2}` → `60→62 {2}` → `{4}`        |
| `double`           | ×    | 두 배 하기         | 짝수 단               | `7×4={28}` → `28+28={56}`                |
| `minus-one`        | ×    | 하나 빼기          | ×9류                  | `10씩 7묶음={70}` → `70−7={63}`          |

### 표기와 범위는 2학년 안에서 완결한다 (교육과정 리뷰 반영)

- **피연산자·결과를 두 자리로 제한하지 않는다 — ⑧은 철회됐다(2026-08-04, 사용자 결정. 코드는 세 자리를 낸다).** 개정 리뷰가 "세 자리는 세로셈의 몫"이라며 제한을 제안했으나, 받아올림 있는 (두 자리)+(두 자리)는 2학년 1학기 범위([2수01-05])이고 결과가 세 자리가 되는 것이 정상이다. 세로셈 존의 `add2-carry`도 이미 110까지 낸다 — 전략 존만 좁힐 이유가 없다. **이 절을 근거로 코드를 좁히지 말 것.** 실제로 세 자리를 내는 것은 덧셈 2종뿐이다(전수 실측: `make-ten` 2304쌍 중 1296쌍·최대 178, `round-adjust` 1264쌍 중 중간값 기준 718쌍·최대 179). 뺄셈 4종은 `a <= 99`가, 곱셈 2종은 구구단 범위가 이미 두 자리를 강제한다
- `double`의 두 배 step은 `28×2`가 아니라 **`28+28`로 찍는다** — 두 자리 × 한 자리 표기는 3-1([4수01-04])이라 아이가 배운 적 없는 형식이고, 실제로 하는 행위도 "두 번 더하기"다
- `minus-one`의 첫 step은 `10×7`이 아니라 **`10씩 7묶음`으로 찍는다** — 10단은 곱셈구구 밖이지만 묶어 세기는 2-1 완료 개념([2수01-10])이라 같은 값을 배운 표기로 묻는다
- `count-up`은 **차 3\~15이고 빼는 수의 다음 10이 두 수 사이에 있을 때만** 생성한다. 차가 크면 중간 빈칸이 그 자체로 두 자리 뺄셈이 되어 전략의 이점이 사라진다 — 원문 예시(63−28, 차 35)가 바로 그 경우라 표의 예시를 근접 쌍(62−58)으로 교체했다

### 도입 순서와 게이트

배열 순서가 곧 도입 순서다: **make-ten → split-place → round-adjust → split-subtrahend → anchor → count-up → [곱셈 게이트] double → minus-one**

- `make-ten`이 앞인 이유: 2-1 교과의 핵심이라 이미 친숙 — 첫 성공 경험(1단을 앞세웠던 것과 같은 원리). 덧셈·뺄셈을 교차시키고, 발상 전환이 큰 `count-up`("빼기를 채우기로")은 뒤로. 순서 변경 비용은 낮다 — "다음에 무엇을 꺼낼지"만 정한다
- **새 전략 도입**: 최신 도입 전략의 출제 횟수(`appearances`) ≥ 3이면 다음을 연다. **채점이 아니라 등장 기준** — 이 게이트의 목적은 숙련 판정이 아니라 노출 페이스 조절이라, 채점이 며칠 밀려도 도입이 멈추지 않는다. 약 3일에 1개, 8종 도입에 약 한 달
- **곱셈 2종은 fluent 식 10개 이상일 때만** 연다(명명 상수, `CHECKUP_MIN_FLUENT`와 같은 발상). 구구단표가 머리에 없으면 `7×4×2`는 우회로가 아니라 짐이다

### 하루 2문항 로테이션

- 문항1 = **오늘의 방법**: 최신 도입 전략 (게이트 통과 시 이 자리에서 새 전략이 처음 등장)
- 문항2 = **어제의 방법**: 이전 도입 전략 중 **가장 오래 출제되지 않은 것** (유지 복습). 전략이 하나뿐인 첫 사흘은 둘 다 그 전략
- **정착기 — 다음 전략을 열 수 없으면 문항1도 로테이션한다**: 최신 전략이 등장 3회를 채웠는데 열 것이 없으면(8종 완료, 또는 곱셈 게이트 대기) 문항1 = 가장 오래 출제되지 않은 전략, 문항2 = 그다음으로 오래된 것. 이 규칙이 없으면 8종 도입 뒤 문항1이 영원히 `minus-one`에 고정되고, 곱셈 게이트 대기 중엔 `count-up`만 매일 나온다. 8종 정착기의 등장 주기는 전략당 4일 — "전략은 레벨이 아니라 체크리스트"(원문 §6.4)가 정착기에도 지켜진다
- **같은 수식 두 방법**(원문 §6.4): 문항2의 전략이 문항1과 **연산이 같고** 수 조합에 `applicable`하면 확률 20%(rand 주입)로 같은 `a, b`를 재사용 — "답이 똑같이 나오는 것을 눈으로 보는" 배치. 연산이 다르면 같은 `a, b`라도 다른 식(`27+15` vs `27−15`)이 되어 목적 자체가 깨지므로 재사용하지 않는다

### 파생과 폴백

- `deriveStrategies(days)` → `Record<StrategyId, { attempts: boolean[]; introducedAt: string | null; appearances: number; lastAppearedAt: string | null }>`. 로그 재생 전용, 저장 없음. `attempts`는 채점된 O/X만, `appearances`는 sheet 등장 횟수(채점 무관, 게이트의 근거), `lastAppearedAt`은 마지막 등장일(로테이션 "가장 오래 안 나온 것"의 근거). `StrategyState`에 파생 전용 필드 2개가 추가되지만 저장되는 값이 아니므로 마이그레이션 없음
- 각 `gen`은 `vertical.ts`처럼 기각 표집이고, 실패 시 **`split-subtrahend`로 폴백**(원문이 "언제나 안전"으로 못박은 전략). 빈 문제지는 절대 내지 않는다

## 4. 문장제 (`engine/word.ts`)

**하루 2문항 = 묶어 세기(`mul-group`) 1 + 몇 배(`mul-times`) 1.** 그림 칸(`needsDrawing`)은 묶어 세기 문항에 붙는다 — "묶어 세기를 그림으로 나타내기"가 교육과정 핵심(원문 §6.5).

**문장제에는 곱셈 게이트가 없다 — 의도된 비대칭이다.** 전략 존의 곱셈 2종은 구구단 인출을 전제하므로 fluent 게이트 뒤에 있지만, 묶어 세기·몇 배는 2-1 완료 개념([2수01-10])이고 첫 문항의 그림 칸으로 세어서도 답에 도달할 수 있어 구구단이 아직 안 외워졌어도 짐이 되지 않는다.

### 템플릿 구조

태그당 문형 4\~5개 × 소재 목록(사탕/구슬/연필/딸기/색종이/쿠키/귤/스티커 — 이름·세는 단위·담는 단위)의 조합. 문형은 두 종류를 허용한다: **소재 슬롯형**(소재 목록에서 채움)과 **활동형**(줄넘기·종이배처럼 소재가 문형에 내장, 단위도 문형이 정함 — "몇 번"·"몇 개"). 중복 회피 키는 소재/활동의 이름이다.

- **조사 처리**: 받침 유무를 유니코드로 계산해 이/가·은/는·을/를을 붙인다 (시뮬레이션으로 검증됨)
- **수사+단위 직결 금지**: "2주머니에는"이 아니라 "주머니 2개에는" — 문형 자체가 이 형태를 갖는다 (시뮬레이션이 잡은 결함)
- **이름 슬롯**: `childName`·`friendNames`를 rand로 배치하되, **하루 두 문항 중 하나엔 반드시 딸 이름**이 들어간다 (시뮬레이션이 잡은 결함 — 딸이 안 나오는 날이 있었다)
- **텍스트는 생성 시점에 완성되어 `sheet`에 박제**된다. 설정에서 이름을 바꿔도 이미 만든 날의 문제지는 변하지 않는다 — 재인쇄 불변식이 자동으로 지켜진다

### 수 선택

- 묶어 세기: `a, b ∈ 2~9`
- 몇 배: 기준량 `∈ 2~9`, **배수 `∈ 2~5`** — "줄넘기 8번의 8배"류가 부자연해서다(시뮬레이션 확인). 구구단 폭 커버는 스프린트의 몫이고 문장제는 상황→식 번역이 목적
- `expression`("4×8")·`answer`·`unit`은 채점 화면과 답 칸("답: ___ 개")에 쓰인다

### 중복 회피

두 문항이 같은 곱셈식·같은 소재·같은 등장인물 조합을 쓰지 않고, 같은 날 전략 존의 곱셈 전략 수식과도 겹치지 않는다 — `compose`의 공유 중복 집합에 함께 들어간다.

### 채점

최종 답(숫자)만 O/X. 그림 칸·식 작성 여부는 채점 대상이 아니다(원문: "전부 ⭕가 기본값이고 틀린 것만 탭").

## 5. 조립과 인쇄 (`compose.ts` · `print-sheet.ts`)

### 조립

```
sheet = [ 세로셈 8 (v1~v8), 역연산 2 (inv1~inv2), 전략 2 (s1~s2), 문장제 2 (w1~w2) ]
```

- 순서가 곧 인쇄 순서이자 채점 번호(①~⑭)의 근거. `ITEM_MARKS`는 이미 ⑭까지 있다
- 중복 집합 하나를 전체가 공유: 세로셈 수식, 전략·문장제의 곱셈식, 문장제 소재·등장인물
- mood 하향 조정(세로셈 8→6)이 걸려도 전략 2 + 문장제 2는 고정 (원문 §6.6 — 총 12문항)
- 생성 실패 폴백·빈 문제지 금지 불변식 유지

### 인쇄

`.sheet` 블록 두 개 + `page-break-after: always`. 인쇄 버튼 한 번에 단면 2장 연속 출력.

- **1장**: 현행 그대로 (세로셈 2열×4행 + 역연산)
- **2장**: 섹션 3 "방법을 따라 풀어 보세요" — **테두리 박스**("천천히 생각하는 칸", 원문 §8의 시각적 분리) 안에 전략 2문항. 각 문항은 수식 + 전략 이름(작게) + `steps`의 `{}`를 빈칸 네모로 치환한 줄들. 섹션 4 "읽고 답해 보세요" — 문장제 2문항, 첫 문항에 빈 사각형 그림 칸(테두리만 — 잉크 최소화), 답 칸에 단위 미리 인쇄("답: \_\_\_ 개")
- 기존 인쇄 CSS 원칙 유지: A4 12mm, 배경색 최소, **정답은 인쇄하지 않는다**
- 전략 렌더러는 `steps`만 아는 단일 함수 — 새 전략 추가 시 인쇄 코드 무변경

### 갱신 경계

Phase 4 배포 직전에 만들어진 10문항짜리 `sheet`는 그대로 10문항으로 인쇄·채점된다 — 소급 재생성하지 않는다(재인쇄 불변식이 우선).

## 6. 채점과 리포트

### 채점 화면 (`grade.ts`)

- `markMap`이 인쇄 순서 그대로 전략→문장제까지 번호를 이어 붙인다(①~⑭)
- 라벨: 전략 `27 + 15 (10 만들어 더하기)`, 문장제 `문장제 4×8 (답 32개)` — 아빠는 종이를 보며 채점하므로 번호·식·정답이면 충분하다
- `grades`에는 여전히 문항 id → boolean만 쌓인다. 구조(전부 ⭕ 기본, mood 1탭) 무변경

### 주간 리포트 (`report.ts`)

- **`배운 방법 N / 8`** (딸 쪽 상단) — `introducedAt !== null`인 전략 수. "전략은 레벨이 아니라 체크리스트"(원문 §6.4)의 화면 표현
- **유형별 정답률에 전략 행 추가** (아빠 쪽 하단) — 원문 §8: "세로셈·역연산·전략의 유형별 정답률". 기존 표본 규칙 그대로(10회 미만 "표본 부족", 90% 미만 ⚠️). **전략은 하루 2문항이라 처음 몇 주는 대부분 "표본 부족"이 정상이다 — 결함으로 오인하지 말 것**
- 문장제 정답률 행은 넣지 않는다 — 원문 §8 목록에 없음(YAGNI)

## 7. 테스트 전략

실패 패턴 6종 + Phase 3 교훈("각 단언마다: 구현이 그럴듯하게 틀렸다면 이 값이 무엇이 되는가" + 변이 검증) 준수.

- **전략 카탈로그**: 8종 각각 — `gen`의 수 조합이 강한 조건을 만족하는지 **독립 술어로** 검사(`carryCount`/`borrowCount` 재사용 — 생성기가 거른 값을 같은 술어로 재검사 금지), `steps` 마지막 빈칸 == `answer`, 각 step 산술 자기일치. 2학년 표기 경계: `double`·`minus-one`의 step 텍스트에 두 자리 `×` 표기가 없는 것, `count-up`의 차 3~15·십 경계 조건
- **도입·로테이션**: 등장 3회 게이트 경계 양쪽, "가장 오래 안 나온 것" 로테이션이 그럴듯한 오류(항상 첫 전략 선택)와 **다른 결과**를 내는 픽스처, 곱셈 게이트 fluent 9/10 경계. 정착기: 8종 완료·게이트 대기 픽스처에서 문항1이 최신 고정이 아니라 로테이션하는 것(그럴듯한 오류: 영구 고정), 같은 수식 재사용이 다른 연산 간에는 일어나지 않는 것
- **문장제**: 받침 조사 양쪽, 배수 2~5 범위 경계, 하루 한 문항 이상 딸 이름, 중복 회피가 실제로 구별되는 픽스처
- **compose 통합**: 14문항·id 순서·공유 중복 집합. 시그니처 변경에 따른 기존 테스트 갱신
- **풀 개편 재측정**: `toContain(81)`→72, 바닥값·굶주림 상한을 실측으로 재유도(추측 금지, 어긋나면 조사 후 주석에 새 실측값과 사유). 무작위 도입의 결정성(`rand` 주입) 확인
- **시뮬레이션 확장**: 전략 채점을 모델에 넣어 다일 재생으로 8종 도입 도달·로테이션 무굶주림 확인(정착기 포함 — 전략당 최대 등장 간격에 상한이 있는지)
- 인쇄·채점 화면은 관례대로 화면 테스트 없음 — 로직은 전부 엔진에
