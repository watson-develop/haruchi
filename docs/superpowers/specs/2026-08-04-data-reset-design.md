# 데이터 초기화 설계 (2026-08-04)

부모 화면에 "모든 기록 지우기"를 추가한다. 기록 전체(`days`)와 설정(`meta`)을 한 번에 비워
앱을 설치 직후 상태로 되돌린다.

## 1. 왜

세 가지 상황이 같은 동작 하나를 필요로 한다.

- 개발하며 쌓인 연습·테스트 기록을 지우고 실사용을 시작할 때
- 아이가 진도를 처음부터 다시 시작할 때
- 아이패드를 정리하거나 넘겨줄 때 딸의 기록을 남기지 않을 때

셋 다 "전부 지운다"로 동일하다. **설정을 편집하는 화면이 이 앱에 없기 때문이다** —
`putMeta`를 부르는 곳은 `screens/report.ts`의 `lastExportedAt` 갱신 한 곳뿐이고,
`Settings`는 늘 `DEFAULT_SETTINGS` 그대로다. 그래서 "기록만 지우고 설정은 남긴다"는
변형은 지울 것이 없는 변형이다. 만들지 않는다.

## 2. 범위

**만드는 것**: 전체 초기화 하나. 버튼 하나, 확인 배너 하나, 데이터 경로 하나.

**만들지 않는 것**: 날짜별 선택 삭제. 화면(날짜 목록)도 위험도(되돌릴 수 있는 수준)도
다른 기능이라 따로 설계한다. 채점을 잘못 저장한 날을 되돌리는 경로는 지금도 없고
(`screens/print-sheet.ts`의 `다시 만들기`가 채점 있는 날을 거부한다), 이번 작업 뒤에도
없다 — 실제로 필요해졌을 때 그 요구를 보고 설계한다.

## 3. 화면

### 자리

`#/report`(주간 리포트) 하단, `가져오기 (복구)` 바로 아래.

```
[ 공유하기 ]
[ 데이터 내보내기 (백업) ]
[ 가져오기 (복구) ]
[ 모든 기록 지우기 ]      ← 새로 생기는 것
[ ← 홈 ]
```

부모 홈(`#/parent`)이 아니라 여기인 이유가 둘이다. 첫째, 이 자리가 이미 "데이터 관리"
무리이고 확인 배너를 그리는 `#confirm` 패널이 여기 있다. 둘째, 부모 홈은 인쇄·채점을
매일 누르는 화면이라 그 옆에 파괴 버튼을 두면 오탭이 실재하는 위험이 된다. 홈에서 한 번
더 들어와야 닿는 자리가 이 버튼에 맞다.

### 렌더 조건

**기록이 0일이면 버튼을 그리지 않는다.** `#share`가 이미 `navigator.share` 유무로 조건부
렌더라 패턴이 있고, 지울 것이 없는데 파괴 경로를 열어 둘 이유가 없다.

### 확인 배너

버튼을 누르면 `#confirm`에 배너를 그린다. 내보내기 확인·가져오기 확인과 같은 패널을
쓴다 — 셋은 서로 덮어쓸 뿐 동시에 뜨지 않는다.

```
42일치 기록(2026-06-01 ~ 2026-08-04)을 지우고 처음 상태로 되돌립니다.
되돌릴 수 없어요.

⚠ 아직 채점하지 않은 문제지가 1일치 있어요 — 그 종이는 채점할 수 없게 됩니다.
⚠ 마지막 백업: 12일 전

[ 네, 지울게요 ]  [ 취소 ]
```

- 첫 줄의 일수·날짜 범위는 가져오기 배너와 같은 형식이다. 무엇을 지우는지 숫자로 보여준다
- **미채점 경고는 미채점 문제지가 있을 때만** 나온다(§5). 아이가 지금 풀고 있는 종이가
  갈 곳을 잃는 것이 이 기능의 유일한 조용한 부작용이라, 그것만 따로 말한다
- **백업 줄은 항상 나온다.** 값이 없으면 `⚠ 백업한 적이 없어요`, 있으면
  `⚠ 마지막 백업: N일 전`(N이 0이면 `오늘`). 되돌릴 수 없는 삭제 앞에서는 하루 전 백업도
  경고할 값이 있어서 `⚠`를 조건부로 붙이지 않는다
- **막지는 않는다.** `lastExportedAt`은 "저장했나요? → 네"라는 사람의 대답으로만 갱신되고
  (`screens/report.ts`의 `triggerDownload` 주석) 파일이 실제로 저장됐다는 보장이 아니다.
  이 값을 강제 게이트로 쓰면 거짓 안전감을 준다. 기기를 넘겨주려는 상황처럼 백업이
  불필요한 경우도 있다. 사실만 보여주고 판단은 사람에게 맡긴다

### 동작

- `네, 지울게요`를 누르는 즉시 그 버튼을 `disabled`로 만든다. 이중 탭 가드다 — HANDOFF가
  `#confirm-replace`에 없다고 이월해 둔 항목이라, 새로 만드는 쪽에는 처음부터 넣는다
- 성공하면 `#/parent`로 이동한다. 가져오기와 같은 사후 동작이고, 부모 홈의
  `✅ 0일 완료 · 🔥 0일 연속`이 결과 확인이 된다
- 실패하면 `showError('지우지 못했어요 (기록은 그대로예요): …')`. `replaceAll`이 원자적이라
  이 문구는 참이다(`data/db.test.ts`가 고정한다)
- 비동기 콜백은 가져오기와 같이 `location.hash !== at`이면 아무것도 하지 않는다. 사용자가
  그 사이 다른 화면으로 갔을 때 남의 화면을 건드리지 않기 위해서다
- `취소`는 배너만 지운다

## 4. 데이터 계층 — `src/data/db.ts`

```ts
export function defaultMeta(): Meta
export async function resetAll(): Promise<void>
```

`resetAll()`의 내부는 `replaceAll([], defaultMeta())`다. **새 트랜잭션 경로를 만들지
않는다** — `replaceAll`은 `put()`이 동기로 던지는 동안 `clear()`만 커밋되어 데이터가 조용히
사라지는 함정을 `tx.abort()`로 막고 있고 그 함정이 테스트로 고정돼 있다. 두 번째 파괴적
경로를 만들면 같은 함정을 다시 밟을 자리가 생긴다.

`defaultMeta()`는 지금 `getMeta()` 안에 인라인으로 있는 기본 Meta 생성을 그대로 뽑은
것이다(`emptyDerived()` + `DEFAULT_SETTINGS` 얕은 복사 + `friendNames` 배열 별도 복사).
`getMeta()`도 이 함수를 쓰도록 바꾼다. **뽑지 않으면 "초기화된 상태"와 "한 번도 안 쓴
상태"가 두 곳에 따로 적혀 갈라진다** — 이 레포가 단일 출처를 고집하는 바로 그 이유다.

초기화 후 `meta` 스토어에는 기본 Meta 레코드가 들어 있고, 한 번도 안 쓴 상태에서는
레코드가 없다. `getMeta()`가 두 경우를 같은 값으로 돌려주므로 앱이 보기에 둘은 구별되지
않는다.

## 5. 엔진 계층 — `src/engine/report.ts`

배너가 쓰는 사실 두 개를 순수 함수로 만든다. 화면은 계산하지 않는다.

```ts
/** 마지막 백업 이후 지난 일수. 값이 없거나 날짜로 파싱되지 않으면 null. */
export function daysSinceExport(meta: Meta, today: string): number | null

/** 문제지를 인쇄했지만 채점하지 않은 날의 수(오늘 포함). */
export function ungradedSheetCount(days: Day[], today: string): number
```

`daysSinceExport`는 `weeklyReport` 안에 인라인으로 있는 `lastDiff` 계산을 뽑은 것이고,
`weeklyReport`가 이 함수를 쓰도록 바꾼다. 파싱되지 않는 값을 `null`로 취급하는 것은
`weeklyReport`가 이미 정한 규칙 그대로다 — `NaN >= 30`이 항상 false라 30일 배지가 영원히
안 뜨는 쪽으로 조용히 실패하는 것을 막으려고 "백업한 적 없음"과 같게 다룬다.

`ungradedSheetCount`는 `sheet.length > 0`이고 `grades`가 비었으며 `date <= today`인 날을
센다. 기존 `pendingGradeDate`를 재사용하지 않는 이유: 그쪽은 `d.date >= today`를 건너뛴다.
"지금 채점하러 가기" 링크가 오늘을 가리키면 안 되기 때문인데, 초기화 경고는 **오늘 아침에
인쇄해 아이가 지금 풀고 있는 종이**가 가장 중요한 대상이라 정반대다. `date <= today`
조건은 가져온 백업에 미래 날짜가 들어 있는 경우를 위한 것이다 — `validateBackup`은 날짜
형식만 보고 범위는 보지 않는다.

## 6. 불변식 점검

| 불변식           | 판정                                                                                                                                          |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 재인쇄 동일성    | 초기화 후 `#/print`가 새 sheet를 만드는 것은 `if (!day \|\| day.sheet.length === 0)` 게이트의 정상 동작이다. 자동 재생성을 새로 만들지 않는다 |
| 손에 든 종이     | 초기화는 인쇄된 종이를 무효로 만든다. 되돌릴 방법이 없으므로 배너의 미채점 경고가 이것을 감당한다(§3)                                         |
| `derived` 비배선 | `defaultMeta()`가 `emptyDerived()`를 넣을 뿐이다. 파생값을 저장하는 코드를 새로 만들지 않는다                                                 |
| 아이/부모 소속   | 버튼은 `#/report`(부모) 안에 있고 새로 생기는 `navigate`는 `#/parent` 하나다. 아이 화면으로 가는 경로를 만들지 않는다                         |
| 단일 출처        | `defaultMeta()`·`daysSinceExport()` 추출로 복제를 오히려 하나씩 줄인다                                                                        |
| 빈 `sheet`       | `ungradedSheetCount`가 `sheet.length > 0`을 먼저 본다. 스프린트만 한 날은 세지 않는다                                                         |
| `escapeHtml`     | 배너에 들어가는 값은 숫자 세 개와 날짜 두 개다. 날짜는 `DATE_RE`로 검증되지만 백업을 거쳐 온 값이라 `escapeHtml`을 통과시킨다                 |
| 배포 URL         | 건드리지 않는다                                                                                                                               |

## 7. 테스트

DOM·화면 테스트는 하지 않는다(설계 §12). 붙는 것은 둘이다.

**`src/data/db.test.ts`**

- `resetAll()` 후 `getAllDays()`가 빈 배열이고 `getMeta()`가 기본값이다
- 초기화 전 `putMeta`로 넣어 둔 `lastExportedAt`이 남지 않는다
- `defaultMeta()`가 부르는 쪽마다 새 `friendNames` 배열을 준다(한쪽을 변형해도 다른 쪽이
  안 바뀐다). 지금 `getMeta()`의 주석이 경계하는 그 공유를 추출 후에도 유지하는지 본다

**`src/engine/report.test.ts`**

- `daysSinceExport`: `null` → `null` / 정상 ISO → 일수 / 파싱 불가 문자열 → `null`
- `ungradedSheetCount`: 채점 완료 / 미채점 / 빈 sheet(스프린트만 한 날) / 미래 날짜
- `weeklyReport`의 `exportOverdue`가 추출 후에도 같은 값을 낸다

**변이 검증을 반드시 돌린다.** `daysSinceExport`가 파싱 불가를 `null` 대신 `NaN`으로
돌려주게 바꿔 그 테스트만 빨개지는지 확인하고 원복한다. 이 레포에서 반복해 잡힌 결함이
"테스트가 자기가 검사한다고 주장하는 것을 실제로는 검사하지 못함"이다.

## 8. 작업 경로

다른 세션이 `seed-design`에서 `main.ts`·`ui.ts`·`styles/`를 만지고 있어 **워크트리**에서
작업한다(CLAUDE.md 작업 경로 ②). 브랜치는 `main` 기반이다 — 이 기능은 SEED 토큰 작업과
독립이고, `seed-design` 위에 얹으면 SEED가 머지될 때까지 배포할 수 없어진다.

머지 직전에 `npx prettier --check .` · `npm test` · `npm run build`를 워크트리 안에서
전부 통과시킨다. 문서를 포함해 모든 커밋을 워크트리 안에서 한다.

## 9. 남기지 않는 결정

- **타이핑 확인(날짜 입력)을 넣지 않는다.** 아이패드 입력이 번거롭고, 이 앱의 다른 파괴적
  동작(가져오기 = 전체 교체)이 2단계 확인만 쓴다. 혼자만 다르면 일관성이 깨진다
- **백업 강제를 넣지 않는다.** §3에 적은 대로 `lastExportedAt`이 신뢰할 수 있는 신호가
  아니다
- **서비스 워커 캐시를 지우지 않는다.** 캐시에는 앱 자산만 있고 딸의 기록은 IndexedDB에만
  있다. 초기화가 다루는 것은 데이터다
