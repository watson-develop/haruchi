# 부모 홈에서 구구단 지도 입구를 없앤다 — 설계

**날짜:** 2026-08-05 **상태:** 승인됨(사용자), 구현 대기

부모 홈의 「구구단 지도」 링크를 없애고, 아이 전용이 된 지도 화면의 뒤로가기를
`← 아이 화면`에서 `← 홈`으로 되돌린다.

## 왜

**① 그 버튼은 부모를 아이 화면에 떨어뜨린다.**

`map.ts`는 아이 소속 화면이라 뒤로가기가 `#/`로 고정돼 있다. 부모가 부모 홈에서
지도로 들어가면 곧장 왔던 자리로 돌아갈 길은 없다 — 지도 → `#/`(아이 홈) →
`부모 →`를 거치는 두 탭짜리 우회로만 남는다. 이 마찰 자체는
`specs/2026-08-04-role-based-ui-design.md`가 이미 이름 붙이고 받아들인 것이라,
①만으로는 입구를 없앨 근거가 되지 못한다 — 그 증거가 EBS다. EBS도 똑같은 모양의
편도 마찰을 지니는데(아이 소속, 뒤로가기가 `#/` 고정) 부모 홈 입구를 그대로
유지하기로 했다. 그리고 이 우회로는 고칠 수 없다: 지도가 `#/parent`로 돌아가게
만들면 아이가 지도를 통해 부모 화면으로 새는 경로가 열리고, 그건 CLAUDE.md의
소속 불변식이 막는다(채점 화면이 모든 정답을 표시하므로 경로가 하나라도 생기면
정답이 노출된다. 잠금·PIN이 없어 이 규칙이 유일한 방어선이다).

**② 부모는 이미 지도를 더 나은 형태로 보고 있다.** 이 근거는 지도에만 해당하고
EBS에는 해당하지 않는다 — EBS를 대신할 "더 나은 형태"가 리포트 등 다른 화면에
없다. ①이 두 화면 모두에서 동일하게 약한 반면 ②는 지도에서만 성립한다는 것이
지도는 입구를 없애고 EBS는 유지하는 이유다.

`report.ts`가 같은 `factMapHtml`을 리포트 안에 싣는데, 이쪽은 인자가 하나 더 붙는다:

```ts
factMapHtml(facts, new Set(w.newlyFluent)) // 리포트 — 이번 주 새로 뚫린 칸 강조
factMapHtml(facts, undefined, { invite: true }) // 지도 화면 — 강조 없음
```

부모 홈의 「구구단 지도」는 **정보가 더 적은 쪽**으로 가는 링크였다. 바로 위
「리포트」 버튼 안에 더 나은 버전이 들어 있다.

## 하루 전 결정을 뒤집는 이유 — 다음에 같은 왕복을 하지 않기 위해

2026-08-05 UX 라운드 1의 P2-8은 지도·EBS의 뒤로가기를 `← 홈`에서 `← 아이 화면`으로
바꿨다. 근거는 **"두 홈 모두에서 진입하는 공용 화면이니 목적지가 라벨이 되어야
한다"**였다.

이 설계는 그 근거의 **전제를 없앤다.** 지도가 아이 전용이 되면 부모 독자를 위해
쓴 라벨이 읽힐 자리가 사라진다 — 아이에게 `#/`는 그냥 홈이다. 즉 P2-8은 틀린
결정이 아니었고, 공용 화면이라는 구조 자체가 문제였는데 그때는 라벨로 덮었다.
이번엔 구조를 고치므로 라벨이 원래대로 돌아가는 것이다.

EBS는 부모 홈 입구를 유지하므로 **`← 아이 화면`을 그대로 쓴다.** 아이 홈에서 지도와
EBS가 나란히 붙어 있는데 뒤로가기 라벨이 서로 달라지지만, 그것이 각 화면의 실제
진입 경로를 반영한 결과다.

`.sep`은 두 링크 사이의 가운뎃점이므로 지도를 지우면 함께 지운다 — 남기면 EBS 앞에
고아 구분자가 붙는다.

## 하지 않는 것

- **EBS 입구는 건드리지 않는다.** 부모가 "오늘 뭘 보여줄까"를 고르는 계획 도구로
  쓸 여지가 있어 지도와 성격이 다르다(사용자 판단, 2026-08-05).
- **「리포트」 버튼의 sub 라벨을 고치지 않는다.** 지도가 리포트 안에 있다는 사실을
  라벨에 명시하는 안(접근법 B)을 검토했으나 채택하지 않았다 — 리포트는 주 1회
  자동으로 열리므로 몇 번이면 알게 되고, sub 라벨은 *언제 열리는지*를 말하는 편이
  부모에게 더 필요하다. 라벨에 기능 목록을 나열하기 시작하면 계속 길어진다.
- **`ebs.ts`의 가드 주석은 그대로 둔다.** EBS 자기 얘기이고 EBS의 라벨은 안 바뀐다.
- **`#/map` 라우트를 없애지 않는다.** 아이 홈에서 여전히 들어간다.
- **테스트를 추가하지 않는다.** 화면 변경이고 엔진은 건드리지 않는다(설계 §12).

## 불변식 확인

- **소속 분리:** 새 `navigate()`가 없다. `map.ts`의 목적지는 `#/` 그대로이고 라벨만
  바뀐다. 부모 홈에서 아이 소속 화면으로 가는 입구가 하나 줄어드는 방향이다
- **재인쇄 동일성·`derived` 비배선·XSS 경계:** 이 설계가 닿지 않는다
- **단일 출처:** 새 값·새 토큰이 없다
- **문서 포맷:** `docs/`를 커밋하기 전 `npm run format` (CI의 `prettier --check .`가
  마크다운까지 본다)

## 검증

`npx prettier --check .` · `npm test`(303) · `npm run build`.

화면 확인(DOM 테스트가 없으므로 사람이 본다):

1. 부모 홈의 링크 행에 「EBS 강의」만 남고 앞에 고아 `·`가 없는지
2. 아이 홈 → 구구단 지도 → 뒤로가기가 `← 홈`이고 아이 홈으로 가는지
3. 부모 홈 → EBS는 그대로 `← 아이 화면`인지
4. 리포트 안의 지도는 변화 없는지
