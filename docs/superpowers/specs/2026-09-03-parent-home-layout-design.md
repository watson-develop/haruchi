# 부모 홈 재구성 — 설계

2026-09-03. 점검 배너를 붙이고 나서 실기기에서 부모 홈을 보니 화면이 무너져 있었다
(사용자: "ui가 너무 별로다"). 배너 하나의 문제가 아니라 **알림이 늘 때 화면이 버티지
못하는 구조**의 문제라, 이 화면 전체를 다시 짠다.

작업 전 `frontend-design` 스킬과 `docs/reference/karrot-DESIGN.md`를 읽었다
(CLAUDE.md 「UI 화면 작업」).

## 0. 무엇이 문제였나 — 실측

dev 서버에 실사용과 같은 상태(격리 1 + 미채점 + 점검 + 동기화 경고)를 넣고 iPad 세로
폭(834px)으로 찍었다.

- **알림 슬래브 셋이 첫 화면을 통째로 먹었다.** 매일 저녁 하는 「문제지 인쇄」·「채점하기」가
  폴드 아래로 밀렸다. 아빠 예산은 1~2분인데(UX 원칙 1) 그 화면은 스크롤부터 요구했다.
- **성격이 다른 알림 셋이 같은 무게로 그려졌다.** 격리(사람이 골라야 끝난다)·미채점(할
  일)·점검(읽고 지나가면 되는 안내)이 전부 전면 틴트 슬래브였다. 무엇이 급한지가 오히려
  사라졌다.
- **꼬리가 밑줄 링크 더미였다.** 「다시 연결하기」·「새 기기 추가」·「EBS 강의」·「← 아이
  화면」이 각자 `div.links` 한 장씩 차지해 44px 간격으로 세로로 쌓였다.
- **인쇄·채점·리포트가 같은 크기 슬래브 셋이었다.** 빈도(매일·매일·주 1회)도 역할도
  다른데 화면은 셋을 똑같이 대했다.
- **✅🔥가 제목과 본문 사이에 가운데 정렬 큰 글씨로 떠 있었다.** 오늘 할 일을 바꾸지
  않는 참고값이 세로 40px를 먹었다.

## 1. 성격 — 이 화면은 무엇인가

**아빠 한 사람이 저녁마다 1~2분 서서 쓰는 운영 콘솔이다.** 대시보드도 랜딩도 아니다.
답해야 하는 질문은 하나다: **"오늘 뭐가 남았나."**

그래서 이 화면의 히어로는 헤드라인이 아니라 **다음에 할 동작**이다.

## 2. 개념 — 「오늘 두 단계 · 알림 한 줄씩 · 조용한 꼬리」

**과감함은 한 곳에만 쓴다.** 화면에서 채도를 가진 것은 **「지금」 칩 하나**이고, 나머지는
전부 무채색으로 물러난다. 그 하나가 "오늘 뭐가 남았나"의 답이다.

### 2-1. 오늘 — 두 단계 한 덩어리 (`.today` / `.todo`)

인쇄 → 채점은 **진짜 순서**다(종이가 나와야 채점할 문항이 있다). 카드 두 장으로 쪼개면
그 순서가 사라지므로 한 덩어리로 묶고 사이를 테두리 한 줄로만 나눈다.

각 단계는 세 상태 중 하나다. **동시에 「지금」인 단계는 하나뿐이다.**

| 상태   | 표식             | 칩                      | 언제                      |
| ------ | ---------------- | ----------------------- | ------------------------- |
| `live` | 브랜드 굵은 링   | 「지금」(주황 솔리드)   | 지금 해야 하는 단계       |
| `done` | positive 체크 원 | 「끝」(positive 텍스트) | 끝낸 단계                 |
| `wait` | 빈 회색 링       | 없음                    | 아직 못 하는 단계(비활성) |

`wait`의 기하는 `live`와 같다 — 인쇄를 마치는 순간 프레임이 튀지 않는다
(당근 §14 Disabled: "Geometry stays identical so re-enable is frame-stable").

### 2-2. 알림 — 한 줄 + 인라인 동작 (`.notice`)

전면 틴트 슬래브를 버리고 **좌측 룰 3px + 한 줄 + 오른쪽 동작 버튼**으로 바꾼다.
세로 점유가 대략 1/3이 된다.

- **성격은 문구와 동작 이름이 나른다** — 「이 기기 것」·「지금 하기」·「리포트 보기」.
- **색은 「사람이 결정해야 하는가」 하나만 구분한다.** 격리만 주황 룰(`notice--decide`),
  나머지는 회색 룰. 다섯 종류가 동시에 뜰 수 있는 화면이라(격리 N + 미채점 + 점검 +
  재기준화 + 거부된 행) 각자 다른 톤을 주면 급한 것이 묻힌다.
- **절 제목에 개수를 적는다**(「알림 3」). 몇 개를 처리하면 이 화면이 조용해지는지가
  아빠에게 실제 정보다. 알림이 0이면 절 자체가 없다.

**부수 효과 — 접근성.** 알림 행이 `div role="button"` + 손으로 붙인 keydown에서 진짜
`<button>`으로 바뀐다. Enter·Space가 브라우저에서 오므로 keydown 핸들러가 통째로
사라지고, SEED 콜아웃의 `:active`가 `button`·`a`에만 걸려 눌림 피드백이 없던 문제
(`2026-09-02-checkup-notice-design.md` §4가 후속으로 미뤄 둔 것)도 함께 닫힌다.

### 2-3. 꼬리 (`.ptail` / `.pmenu`)

구분선 아래로 내리고 **한 줄로 흐르게** 한다. 이 블록의 자식 대부분은 이 화면이 만들지
않는다(`syncHtml`과 인증 실패 응답이 만들어 붙인다) — 그래서 자식을 고치지 않고
컨테이너가 흐름을 정한다(`display: flex; flex-wrap: wrap`). 상태 줄과 등록 패널만
`flex-basis: 100%`로 제 줄을 갖는다.

### 2-4. 머리

날짜와 두 숫자(✅ 완료일·🔥 연속일)를 제목 아래 **한 줄**로 접는다. 🔥·✅ 분리 정책
(설계 §6.8)은 그대로다 — 아이 홈에 🔥, 부모 홈에 둘 다.

## 3. 하지 않은 것

- **새 목적지를 만들지 않는다.** 화면 소속·PIN 게이트·`navigate()` 목적지가 전부
  그대로다(PRD §3 불변). 그래서 이 작업은 PRD를 갱신하지 않는다 — 사용자에게 보이는
  **정책**이 아니라 배치가 바뀐 것이다(CLAUDE.md 「문서」).
- **`.step`을 고치지 않는다.** 열 화면이 공유하는 클래스라 여기서 손대면 앱 전체가
  흔들린다. 「리포트」는 `.step`을 그대로 쓰고, 새 규칙은 전부 `parent.css`의 새 이름에
  둔다(`.todo`·`.notice`·`.phead`·`.psec`·`.ptail`·`.pmenu` — 충돌 없음을 확인했다).
- **아이 화면을 건드리지 않는다**(UX 원칙 2).
- **진입 애니메이션을 넣지 않는다.** 당근 §15는 스프링을 금지하고, `frontend-design`은
  섹션마다 페이드-슬라이드를 "AI가 만든 티"로 지목한다. 이 화면에는 사람의 동작에 답하는
  모션(`:active`)만 둔다.

## 4. 자기검토 — 일반적 기본값을 피했나

`frontend-design`이 지목한 AI 기본값과 대조했다.

- **크림 배경 + 세리프 + 테라코타?** 아니다 — 브리프(SEED)가 방향을 못 박았고 색은 전부
  역할 토큰에서 온다. 차별화는 색이 아니라 **구조**에서 낸다.
- **같은 반경·같은 그림자 카드 킷?** 셋을 다르게 뒀다: 오늘은 묶인 큰 카드(r4),
  알림은 카드가 아니라 좌측 룰만, 리포트는 기존 `.step` 슬래브. 그림자는 없다(당근 §6).
- **ALL-CAPS 아이브로우?** 한글이라 해당 없음. 「오늘」·「알림 3」은 개수를 담은 진짜
  정보다.
- **01/02/03 숫자 마커?** 오늘 두 단계는 진짜 순서지만 숫자 대신 **상태**(링·체크·칩)로
  표현했다. 숫자는 두 개짜리 목록에 과하다.
- **버튼 텍스트 끝의 '→'?** 쓰지 않았다.

## 5. 검증

- `npm test`(490) · `npx prettier --check .` · `npm run build`
- dev 서버 + 주입 데이터로 세 상태를 실제로 찍어 확인했다: ⓐ 알림 3개(격리·미채점·점검),
  ⓑ 조용한 저녁(알림 0, 인쇄 전 — `live`/`wait`), ⓒ 격리 해소 직후(알림 2로 감소).
- 클릭 실측: 「문제지 인쇄」 → `#/print`, 「리포트 보기」 → `#/report`,
  「이 기기 것」 → `wireQuarantine`의 busy → 재렌더.
- 아이 홈이 그대로인지 스크린샷으로 확인.

**구현 중 잡힌 결함 하나.** `noticeAction`을 `attrs: string` 하나로 받게 만들었더니
호출부가 `class="q-adopt"`를 넘기는 순간 `class`가 두 번 찍혀 브라우저가 뒤엣것을
버렸고, `wireQuarantine`의 `host.querySelector('.q-adopt')!`가 null이 되어 부모 홈이
통째로 에러 화면이 됐다. `{ id, cls }`로 나눠 받게 고쳤다. **DOM 테스트가 없는
레포라 이 결함군은 브라우저로 직접 보는 것 말고 잡을 방법이 없다** — 화면 작업에서
스크린샷 검증을 건너뛰지 말 것.
