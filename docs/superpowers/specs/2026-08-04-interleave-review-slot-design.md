# 세로셈 교차 제약 + 마스터 유형 복습 슬롯

작성: 2026-08-04. 전제: Phase 4 완료. `compose.ts`의 세로셈 조립에 학습과학 근거
두 가지를 배선한다. 근거 원문과 논문 매핑은 `docs/reference/learning-science-evidence.md`.

**한 줄 목표**: 세로셈 8문항이 (1) 연속으로 같은 풀이법을 요구하지 않게 하고(교차연습),
(2) 하루 1문항을 오래 안 본 마스터 유형에 예약해 우연에 기대던 복습을 설계로 만든다(분산연습).

## 0. 결정 경위 (브레인스토밍 합의)

| 질문                 | 결정                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------ |
| 복습 방식            | **기회형 슬롯** — 가중 로테이션 유지, 1자리만 예약. 진짜 사다리(1→3→7→14)는 기각     |
| 최소 간격            | **3일** — 구구단 사다리의 두 번째 칸과 일치. 우연 복습(weight 0.1)과 구별되는 최소선 |
| 슬롯 위치            | **v1 (첫 자리)** — Claude 재량 판단, 사용자가 유보 승인. 되돌리기 지점은 §3          |
| "마지막 등장"의 기준 | **인쇄(sheet에 실림), 채점 무관** — `deriveStrategies.appearances`와 같은 원칙       |
| 교차 제약 범위       | **세로셈 내부만** — □ 채우기·전략·문장제는 각 2문항에 유형이 이미 다름               |
| 두 작업의 진행 방식  | **설계 한 번, 구현 순차(교차 → 슬롯)** — 같은 루프를 고치므로 병렬 워크트리는 기각   |

## 1. 왜 지금 이 둘인가

- **교차 제약**: Rohrer et al. (2020) 군집 RCT에서 교차연습 d = 0.83. 근거가 크고 구현이
  리롤 조건 하나다. 단 근거는 중학생 대상 — 초등 직접 근거는 얇다는 것을 알고 차용한다.
- **복습 슬롯**: 수학에서 분산연습 g = 0.28 (Murray et al. 2025). 구구단은 이미
  사다리(`facts.ts`)가 있지만 종이 유형은 "90% 달성 → 개방" 이후 weight 0.1의 우연에만
  기댄다. 슬롯은 그 우연을 설계로 바꾸되 기존 분포는 건드리지 않는다.

## 2. 교차 제약

`composeSheet`의 세로셈 루프(`DEDUP_ATTEMPTS` 재시도)에 조건 하나를 더한다.

- **규칙**: 생성된 후보의 tag가 직전 세로셈 문항의 tag와 같으면 리롤. 수식 중복 회피와
  같은 예산(60회)을 공유한다.
- **비교 대상은 생성된 문항의 tag다.** `generateWithFallback`이 생성 실패 시 더 쉬운
  유형으로 내려가므로, 추첨된 tag로 비교하면 폴백 경로에서 제약이 샌다.
- **비활성**: `openTags(types).length < 2`면 제약 없음 (도입 초기엔 불가능하므로).
- **예산 소진 시**: 인접 동일을 허용하고 넘어간다 — 기존 중복 처리와 같은 원칙
  ("빈 자리를 두지 않는다").

## 3. 복습 슬롯

- **발동**: `everMastered`인 열린 유형 중, `deriveLastSeen` 기준으로 오늘까지
  `diffDays ≥ 3`인 것이 존재할 때. `lastSeen`에 없는 마스터 유형은 이론상 불가하지만
  (숙련은 10회 이상 채점을 요구하고, 채점되려면 sheet에 실렸어야 한다) 백업 가져오기
  등을 대비해 **가장 오래된 것으로 취급**한다. 열린 유형이 1개뿐이면 마스터 유형이
  아직 없다는 뜻이므로 슬롯도 자연히 미발동이다 — §2의 교차 제약 비활성 조건과 같은
  구간에서 함께 꺼진다.
- **선택**: 그중 가장 오래 안 나온 유형. 동률이면 `VERTICAL_ORDER` 앞쪽.
- **위치는 v1**: 슬롯을 먼저 확정하고 나머지를 뽑으면 교차 제약이 "v2가 슬롯 tag를
  피한다"로 순방향으로 풀린다(마지막 자리면 v7 생성 시 미래의 슬롯 tag를 미리 피해야
  하는 역방향 의존이 생김). 마스터 유형으로 시작하니 "쉬운 첫 문제로 예열" 부수 효과도
  있다. **되돌리기 지점**: 위치가 마음에 안 들면 `composeSheet`에서 슬롯 문항을 items
  배열의 다른 인덱스에 끼우면 된다 — 단 그 자리 앞뒤의 교차 제약 처리를 함께 옮겨야
  한다. 파생·저장에는 위치 가정이 없다.
- **미발동 시**: v1도 일반 가중 추첨. 슬롯 문항은 여느 문항처럼 채점·이력 누적(같은
  tag이므로 자동이며, 별도 표시를 저장하지 않는다).
- **생성 실패 시**: `generateWithFallback` 규칙 그대로 폴백.

## 4. 파생·시그니처

```
engine/derive.ts    deriveLastSeen(days): Record<string, string> 추가 — tag → 마지막으로
                    sheet에 실린 날짜. 채점 안 된 날도 센다(§0 "인쇄 기준").
                    everMastered를 export (의미 변경 없음, 공개만).
engine/compose.ts   composeSheet 입력에 lastSeen·today 추가. new Date()를 엔진에서
                    부르지 않는다 — 순수 함수 유지, 테스트 결정성.
engine/dates.ts     기존 diffDays(from, to) 사용. 신규 헬퍼 없음.
screens/print-sheet buildSheet()에서 deriveLastSeen(days)와 dayKey(new Date())를 주입.
```

- **저장 스키마 변경 없음, 마이그레이션 없음.** `TypeState`는 `{ attempts }` 그대로 —
  죽은 필드인 `Derived` 타입과 얽히지 않도록 슬롯용 정보는 슬롯용 파생 함수로 분리한다.
- 재인쇄 불변식 그대로: 슬롯 문항도 `sheet`에 저장되고 재생성되지 않는다.

## 5. 테스트 (전부 `engine/`, 속성 기반)

1. **교차**: 1000회 생성 — 열린 유형 ≥ 2일 때 인접 세로셈 tag 동일 0건. 열린 유형
   1개일 때 제약 없이 정상 생성.
2. **슬롯**: 조건 충족 로그에서 v1 tag가 기대 유형 / 마스터 없음·3일 미만이면 일반
   추첨(1000회 생성에서 v1 tag 분포가 한 유형에 고정되지 않음).
3. **deriveLastSeen**: 채점 없는 날 반영, 마지막 날짜가 이김.
4. **기존 속성 유지**: 수식 중복 없음·문항 수·id 순서.
5. 변이 검증: 제약 조건을 제거해 1번만 빨개지는지, 슬롯 분기를 제거해 2번만
   빨개지는지 확인 후 원복.

## 6. 건드리지 않는 것 (비범위)

- 진짜 간격 사다리(유형별 interval·nextDue) — 기각 근거 §0.
- 예시 풀이(worked examples)·문장제 스키마 회전·문제 만들기 — 근거 문서에 미착수
  후보로만 기록. 각각 별도 브레인스토밍을 거친다.
- `weightsFor`의 가중치 공식 — 변경 없음.
- □ 채우기(inverse)의 숙련 배선 — 여전히 Phase 4 이후 (derive.ts 주석의 기존 결정).
