# 2학년 2학기 계획 — 설계 (2026-08-26)

앱(하루치)과 앱 밖 운영을 함께 다루는 통합 계획이다. 근거 문서:
`docs/reference/integrated-arithmetic-ladder.md` §7(구간 B·C),
`docs/reference/korean-elementary-math-curriculum.md` §3(2-2 단원),
『잠수네 공부법』 초등 1·2학년 수학 절(285~301쪽, 사진 판독).

**결정 요약** — 앱 코드의 방향은 바꾸지 않는다. 코드 변경은 `word.ts`(문장제
소재 문형 4개 + 등장인물 개편)와 `streak.ts` 용서 폭 조정(상수 + 기존 경계
테스트·독스트링 갱신)이고, 나머지는 전부 운영 문서다.

## §0. 배경 — 잠수네 대조

잠수네의 핵심 주장(문제집 강요가 수학 혐오를 만든다 / 계산보다 독해력 /
좋아하게 먼저 / 상위권 공통점은 생활수학·수학동화·퍼즐이지 선행 문제집이
아니다)을 하루치 설계와 대조한 결과:

- **이미 흡수된 긴장** — 소량 고정(14문항 12~15분), mood 신호(😫 3연속 →
  세로셈 8→6 하향, `derive.ts`), 부정 신호 금지·성취만 표시(PRD §4), 지니
  보상, 선행 아님(학교 진도 준비 수준). 표면상 "매일 문제지 앱"이지만
  잠수네가 경고하는 과량·강요 축은 설계가 이미 막고 있다.
- **실제로 영향받는 것은 운영 2건** — ① 앱이 내린 분량 하향을 사람이 뒤집지
  않는다는 합의, ② 채점 때 전략 문항 1개를 말로 설명시켜 개념 구멍과 문장
  이해 실패를 아빠가 분류. 둘 다 §3의 운영 원칙으로 격상한다.
- **명시적 비범위 유지** — 독해력 축은 앱이 먹지 않는다. §2의 문장제 소재
  다양화는 독해력 훈련의 대체제가 아니다(잠수네의 독해력 처방은 한글책·
  수학동화이고 그것은 운영 몫). PRD 비범위("문해력 확장")는 이번에도
  유지된다. "문장제를 길게 쓰면 독해력도 되지 않나"류의 범위 침식을 이
  줄이 막는다.

LLM 런타임 투입(생성 시점 API 호출)은 검토 후 기각했다 — 의존성 0·오프라인·
XSS 방어선("템플릿에 들어가는 값은 우리가 만든 리터럴뿐")·속성 기반 검증·
신호 순도 다섯과 충돌한다. LLM은 지금처럼 설계 시간에 쓰고(문형을 만들고
사람이 검수해 코드 리터럴로 박제), 런타임은 결정론으로 돈다.

## §2. 앱 개발분

### 2-1. 소재 편입: 문형 4개 (`word.ts`)

2-2 비연산 단원 중 길이(cm)·시간(분)을 문장제의 **옷**으로 편입한다. 수학은
여전히 b×a(b·a∈2~9)라서 아이가 해당 단원을 아직 안 배웠어도 풀 수 있다 —
시기 게이트를 두지 않는 근거다(무게이트, 사용자 결정).

`GOODS` 행 추가가 아니라 **소재 내장형 문형**으로 넣는다. GOODS는 이산
사물(개·장·자루) 전제라 측정 단위와 기존 문형의 조합("리본을 한 봉지에
3cm씩")이 깨지기 때문이다. 단, 소재 내장 전례(`key: () => '줄넘기'`,
`unit: () => '번'`)는 **`TIMES_TEMPLATES`에만 있다** — `GroupTpl`에는 unit
필드가 없고 group 문항의 단위는 뽑힌 GOODS 행(`g.unit`)에서 나온다. 그대로
넣으면 길이 문항의 답 칸이 "몇 개"로 인쇄된다. 따라서:

- **`GroupTpl`에 `unit?(g): string` 오버라이드를 추가**하고 생성부를
  `unit: tpl.unit?.(g) ?? g.unit`으로 고친다. 기존 4문형은 무변경(옵셔널).

추가 문형 4개 — 예문의 `${p}`·`${f}`는 인물 슬롯이다(리터럴 아님):

- `GROUP_TEMPLATES` +2 (묶어 세기):
  - 길이: "길이가 4cm인 리본 조각이 3개 있어요. 한 줄로 이어 붙이면 모두
    몇 cm일까요?" — key `'리본'`, unit `cm`. **무인물 문형이므로
    `hasPerson: false`를 반드시 지정**한다(누락 시 유령 인물이 `w-person:`
    seen을 오염 — 재현된 버그 경로, word.ts 주석 참조). 그림 칸은 group
    공통(`needsDrawing: true` 고정)이라 자동으로 받으며 그대로 둔다 —
    리본 3조각은 그리기 자연스러움
  - 시간: "${p}는 동화책을 매일 5분씩 읽어요. 4일 동안 모두 몇 분
    읽을까요?" — key `'동화책'`, unit `분`(기존 '먹다' 문형과 같은 골격).
    그림 칸 유지 — "5씩 4묶음"을 동그라미로 그리는 것은 시간 소재에서도
    성립한다
- `TIMES_TEMPLATES` +2 (몇 배):
  - 길이: "${f}의 리본은 3cm예요. ${p}의 리본은 ${f}의 4배예요. ${p}의
    리본은 몇 cm일까요?" — key `'리본'`(GROUP 길이 문형과 같은 키 —
    하루 안에 리본이 두 번 나오는 것을 `w-goods:` 중복 방지가 차단).
    계사는 `copula('cm')`를 태우지 않고 **'예요' 리터럴**로 박는다.
    `hasBatchim('cm')`은 비한글이라 받침 있음 → copula가 '이에요'를
    내는데, 발음(센티미터, 모음 끝) 기준 표준은 '예요'다
  - 시간: "${f}는 그림을 2분 그렸어요. ${p}는 ${f}의 3배만큼 그렸어요.
    ${p}는 몇 분 그렸을까요?" — key `'그림'`. 줄넘기가 아닌 이유: 기존
    TIMES 문형(key `'줄넘기'`)과 소재가 겹치면 6문형 중 2개가 줄넘기가
    되어 소재 다양화라는 §2 목적과 어긋난다(적대적 리뷰 발견)

기존 계약: `seen`의 `w-goods:` 중복 방지 그대로(리본이 GROUP·TIMES 양쪽에
있어도 같은 키라 하루 내 중복이 오히려 차단됨), 새 문형은 `eligible` 필터가
없어 소재 풀 축소 없음, `WordItem` 타입 무변경(unit은 이미 string, answer는
number 유지)이라 마이그레이션·백업 검증·채점 화면 변경이 없다. 텍스트는
생성 시점 박제라 재인쇄 불변식도 무접촉. expression은 group 생성부의 기존
표기(낱개수×묶음수)를 따라 "4cm 조각 3개" → `4×3`으로 교과 표기와 일치.

### 2-2. 등장인물 개편 (`word.ts`)

딸이 자기 이름 노출 제거를 요청했다(사용자 전달, 2026-08-26).
`WORD_NAMES`를 다음으로 바꾼다:

- `child: '유나'` — 가상 이름. "두 문항 중 하나엔 반드시 child" 규칙(설계
  §6.5)은 유지하되 의미가 몰입에서 **고정 주인공**으로 바뀐다
- `friends: ['지호', '민아', '서연', '도윤']` — 풀 확장(사용자 결정: "이름
  유형을 더 추가"). **받침 있는 이름(서연·도윤)을 포함**해 `personJosa`·
  `personStem`의 받침 분기(`서연이가`·`서연이는`·`서연이의`)가 실사용된다 —
  지금까지 이 분기는 테스트 주입으로만 돌았다

이름 선정 제약(구현 시 다른 이름으로 바꿔도 이 제약은 지킬 것): 보통명사
동음이의어 금지 — '하루'(1일)·'지우'(지우개) 유형은 "민아는 하루의 3배만큼"
같은 오독을 만든다. 마스코트 지니의 이름은 쓰지 않는다 — 지니는 보상
캐릭터(`#/genie`)라 문장제 일상 인물과 세계관이 섞인다.

적용 시점: 바꾼 뒤의 문제지부터(박제 원칙 — 과거 문제지 불변). 당일 치가
이미 만들어져 있으면 「다시 만들기」(채점 전만)가 탈출구다. `word.ts:21`
주석의 옛 실명 언급과 word.test.ts 상단의 "프로덕션 이름이 아니라 받침 있는
이름('서연')을 주입한다" 주석(서연의 프로덕션 편입으로 낡음)도 같은
커밋에서 함께 정리한다.

### 2-3. 주말 공백 용서 (`streak.ts`)

`FORGIVEN_GAPS`를 1 → **2**로 올린다. 근거: §3 루틴이 토·일 스프린트를
"자유(강요 없음)"로 두는데, 현행 1이면 주말 이틀을 쉰 아이가 월요일 홈에서
🔥 18일 → 0~1일 리셋을 본다(스프린트 전 0, 후 1) — §0의 "부정 신호
금지"·강요 금지 원칙과
정면충돌한다(적대적 리뷰 발견). 스트릭은 로그에서 매번 재계산되므로 상수
변경만으로 **과거 기록도 소급 재해석**된다 — 마이그레이션 없음.

**수반 작업**: 기존 경계 테스트(「이틀 연속 빠지면 거기서 끊는다」)가 이
변경으로 빨개지므로 재작성하고, `streak.ts` 독스트링("하루 빠진 것은
봐준다")도 함께 갱신한다. 신규 테스트: 이틀 공백 유지·사흘 공백 리셋 경계 +
변이 검증. `FORGIVEN_GAPS`는 streak.ts 내부 전용이라 다른 소비처는 없다
(`sprintStreak` 소비처는 홈 2곳·리포트 1곳 — 의미가 함께 바뀌는 것은
파라미터 조정 범위).

**수용하는 잔여 리스크**: 용서 예산 2일을 주말이 전액 소비하므로, 주말에
인접한 평일 하루 결석(금 병결 또는 월 병결)은 3일 연속 공백이 되어 여전히
리셋된다. 요일 인지 용서(주말은 예산 미소비)는 복잡도 대비 과해 기각한다
(§2-4) — 실사용에서 이 리셋이 실제로 아프면 상수를 3으로 올리는 것으로
충분하고, 그때도 소급 재해석이라 마이그레이션이 없다.

### 2-4. 넣지 않는 것

- **m 단위** — 2-2의 m은 "cm 100개 = 1m" 단위 감각이 핵심이라 곱셈 옷으로는
  그 학습이 일어나지 않는다. cm로 충분.
- **네 자리 수·표와 그래프·규칙 찾기** — 곱셈 틀(b·a∈2~9) 밖. 운영 몫(§3).
- **시각 읽기**("3시 30분") — answer가 number가 아니게 된다. 스키마 침범.
- **2단계 문장제**(곱셈+덧뺄 합성, 예: "3개씩 4봉지에서 2개 먹으면?") —
  2학년 심화의 정석이자 잠수네 사고력 축과 일치하는 **후보**. 딸이 현행
  문장제를 안정적으로 맞추면(정답률 신호) 별도 스펙으로 연다. 지금은
  범위 밖.
- **요일 인지 스트릭 용서**(주말은 용서 예산을 소비하지 않는 방식) —
  기각. §2-3의 잔여 리스크 항목 참조.

### 2-5. 테스트

기존 속성 검사(1000회 생성)에 새 문형이 자동 포함된다. 추가로: 새 문형
출력 수준 회귀(조사·단위 표기·'예요' 리터럴), **받침 있는 새 friends
이름의 조사 출력 회귀**, **무인물 문형의 `hasPerson: false` 회귀**(유령

해당 테스트만 빨개지는지 확인 후 원복).

## §3. 운영 — 주간 루틴

활동이 규칙이 아니라 "오늘 아빠가 꺼낸 놀이"로 보여야 한다. 루틴의 강제력은
아빠에게만 걸린다(앱이 아이에게 성취만 보여주고 사다리를 뒤에서 돌리는

토·일 "자유"의 스트릭 리셋은 §2-3(FORGIVEN_GAPS 2)이 막는다 — 단, 주말에
인접한 평일 병결까지 겹치면 리셋되는 잔여 리스크는 수용한다(§2-3).
문제지가 월~금뿐이므로 일요일 채점 저장 시 `#/report` 자동 전환(설계 §8,
`grade.ts`)은 타지 않게 된다 — 일요일 리포트는 표의 수동 인쇄로 대체되는
것이며 코드 변경은 하지 않는다(사문화 인지).

**운영 원칙 3개**(잠수네 → 규칙 격상):

1. 앱이 내린 분량 하향(😫 신호)은 사람이 뒤집지 않는다.
2. 채점 때 전략 문항 1개는 말로 설명시킨다 — 막히면 개념 구멍인지 문장
   이해 실패인지 분류한다. 비용은 30초 내외로 PRD의 "아빠 개입 1~2분"
   예산 안이다(익힘책 확인 1분은 별도 항목으로 표에 이미 계상).
3. 앱 밖 활동(책·게임)은 강요 금지 — 싫다면 그 주는 건너뛴다.

**단원 달력(9~12월 개략)**: 네 자리 수(9월) → 곱셈구구(9·10월) → 길이
m,cm(10·11월) → 시각과 시간(11월) → 표와 그래프·규칙 찾기(12월). 익힘책 ★
확인과 생활수학 소재를 이 달력에 맞춘다 — 앱은 진도 비동기.

**보드게임 후보**(잠수네 목록 중 2-2 접점): 루미큐브(수 조합), 우봉고·
펜토미노(도형 감각), 메이크텐(연산). 한두 개로 시작한다.
