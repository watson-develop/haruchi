# 하루치 — PRD (정책서)

**이 문서는 살아있는 문서다.** "지금 이 서비스가 무엇이고 어떻게 운영되는가"만 답한다.
왜 그렇게 됐는지는 `docs/superpowers/specs/`(시점 고정), 언제 무슨 일이 있었는지는
`docs/superpowers/HANDOFF.md`(연대기)가 답한다. 사용자에게 보이는 정책(범위·규칙·역할·
화면 소속)이 바뀌는 커밋마다 해당 절을 덮어쓴다. 내부 리팩터·버그픽스는 갱신하지 않는다.
날짜를 붙이지 않는 이유: 이 레포에서 날짜 붙은 문서는 스냅샷, 날짜 없는 문서는 살아있는
문서다. 300줄을 넘으면 실패다 — 넘치는 세부는 소유자 문서로 밀어낸다.

값을 베끼지 않고 소유자를 가리킨다. 여기 적힌 숫자는 그 자체가 사용자 결정(정책)인 것만이고,
각 값의 구현 소유자를 함께 적는다. 이 문서와 코드가 다르면 코드가 맞고, 이 문서를 고쳐야 한다.

## 1. 무엇인가

초등 2학년 딸의 산수 연습 도구. 개인용 — 사용자는 **딸(초2)과 아빠 둘뿐**이고 계정·로그인이
없다. 매일 아이패드(PWA)에서 3분 구구단 스프린트를 하고, 일요일엔 주간 리포트를 인쇄해
냉장고에 붙인다. 종이 문제지·채점은 2026-09-30 은퇴했다(기록은 보존 — §5).

존재 이유: 아이가 약한 것은 구구단 81개 전부가 아니라 특정 10–15개다. 전면 반복 대신
약한 지점만 데이터로 특정해 때린다. 아빠 개입 1–2분이 예산이다
(근거와 원문: `specs/2026-08-02-haruchi-design.md` §1–3).

## 2. 현재 범위 / 비범위

**범위** — 아이패드 스프린트(구구단 반응시간) + 주간/월간 리포트 + 구구단 지도 + 전정복 보상(지니 — 조건·보상·진척을 아이에게 공개, 소원은 한 번) +
EBS 주제 서가 +
**기기 간 동기화**(Supabase, push·pull·병합) + 부모 화면 PIN 게이트 + 기기 등록(상한 5대)과
관리 화면.

**비범위** — 종이 문제지·채점(2026-09-30 은퇴 — 기록은 보존, 설계:
`specs/2026-09-30-retire-paper-sheet-design.md`) · 나눗셈(3학년, 구조만 열어둠) · 사진 채점(OCR) · 멀티유저·계정 · 문해력·심화
확장. ~~동기화~~는 원 설계의 비목표였으나 2026-08 동기화 1·2단계로 범위에 들어왔다 —
원 설계 §2의 비목표 목록은 그 시점의 기록으로 읽을 것.

## 3. 역할과 화면 소속 — 유일한 방어선

화면은 **아이 소속**과 **부모 소속**으로 고정이고, 아이 화면에서 부모 화면으로 가는
`navigate()` 경로는 하나도 없어야 한다. 부모 화면은 성적 집계(리포트)와 파괴적 작업(관리)을
담으므로 이 규칙이 잠금 대신의 방어선이다(잠금 없음은 사용자 결정).

| 소속 | 해시                                      | 화면                                                    |
| ---- | ----------------------------------------- | ------------------------------------------------------- |
| 아이 | `#/` `#/sprint` `#/map` `#/ebs` `#/genie` | 아이 홈 · 스프린트 · 구구단 지도 · EBS 서가 · 지니 보상 |
| 부모 | `#/parent` `#/report` `#/manage`          | 부모 홈(소원 기록 포함) · 리포트 · 데이터 관리          |

이에 더해 `#/report`·`#/manage`는 **PIN 게이트** 뒤에 있다(§6). 라우팅 소유자:
`src/main.ts`(`GATED_HASHES` 포함).

**아이 기기**(`devices.child = true`, 지금은 이서아 폰)에서는 부모 소속 화면 전체가 PIN과 무관하게
라우터에서 막혀 아이 홈으로 돌아가고, 「부모 →」 버튼도 없다. 표식은 SQL 전용 설정이다
(`supabase/README.md` 6.6). 해제된 아이 기기는 표식이 풀린다 — 서버가 잊은 기기를 영구히
잠그지 않기 위해서다. 설계: `specs/2026-09-29-child-device-design.md`.

점검 결과의 **숫자**(유지·다시 연습)는 그 게이트 뒤(리포트 월간 절)에만 있다 — 부모 홈은
점검일부터 7일간 "결과가 있다"고만 안내한다. 부모 홈이 PIN 밖이기 때문이다.
소유자: `src/engine/checkup.ts`의 `checkupNoticeDate`.

## 4. 학습 정책 — 스프린트

- **구구단 스프린트(아이패드)**: 반응시간이 신호. 중앙값 ≤ 유창 기준 3회 연속 → fluent,
  복습 간격 1→3→7→14일. 소유자: `src/engine/facts.ts`

- **지니 보상**: 램프의 게이지와 점등은 **역대 최고 정복 수**가 정한다(오늘의 정복 수가
  아니다 — 정복은 최근 성적이라 도달 뒤에도 오르내리고, 그때마다 램프가 꺼지면 "다 채우면
  소원"이라는 약속이 거짓이 된다). 티저가 조건·보상·진척을 아이에게 직접 말한다. 아빠가
  부모 홈에서 「소원 들어줬어요」를 누르면 램프는 트로피가 되고 지니는 소원을 다시
  약속하지 않는다(되돌릴 수 있다). 소유자: `src/engine/facts.ts`의 `peakFluent`·`genieState`,
  기록은 `Settings.wishGrantedAt`. 근거: `specs/2026-09-03-genie-contract-gauge-design.md`

아이에게는 성취만 보여준다 — 부정 신호 금지. UX 정책 전체는 `docs/design/ux-principles.md`.
정복·사다리·점검 규칙을 사람 말로 푼 설명은 `docs/design/mastery-rules-plain.md`(값의
주인은 여전히 `facts.ts`·`checkup.ts`).

## 5. 데이터 — 로그는 사실, 파생은 해석

- **원본은 이 기기의 IndexedDB의 `Day` 로그다.** 서버가 아니다. 모든 상태(유창·
  리포트)는 매번 로그에서 재계산하고, 파생값은 저장하지 않는다. 그래서 판정 기준을 고치면
  과거 전체가 소급 재해석되고 마이그레이션이 없다
- 스프린트만 한 날은 `sheet: []`인 `Day`로 실재한다. 종이 은퇴(2026-09-30) 뒤에는 모든 새 날이
  그렇다 — 비어 있지 않은 `sheet`·`grades`는 과거 로그로만 남는다
- 백업 파일과 서버 스냅샷은 같은 모양을 쓴다. 소유자: `src/engine/backup.ts`의 `backupPayload`
- 배포 origin `https://watson-develop.github.io/haruchi/`은 불변 — IndexedDB가 origin에
  묶여 있어 주소가 바뀌면 기록에 접근할 수 없다

## 6. 동기화·접근 정책

흐름: 각 기기가 바꾼 묶음(`sheet`·`grades`·`sprint`·`settings`)을 서버로 push하고, 서버
행이 pull로 내려와 로컬과 병합된다. **무엇이 이기는지는 `src/engine/merge.ts`만 정한다** —
화면도 저장 코드도 정하지 않는다. 판정은 묶음마다 따로 난다.

- **`sheet` 충돌은 병합하지 않는다**(종이 은퇴 뒤에는 과거 기록끼리의 충돌에만 해당). 두 기기가 각자 문제지를 만들었으면 종이가 물리적으로
  두 장이다 — 그 날짜를 격리하고 부모 홈 배너에서 아빠가 고른다. 자동 해소 없음
- pull 적용은 push 표식을 남기지 않는다(메아리 방지). 소유자: `src/data/db.ts`의
  `applyPulled*`
- `sync-config.ts`가 비어 있으면 동기화 전체가 꺼진다(새 배포 환경용 스위치)
- 파괴적 작업(초기화·가져오기·재기준화)은 동기화가 켜져 있으면 **서버 스냅샷 뒤에만** 진행

**PIN 게이트**: `#/report`·`#/manage` 진입 시 풀스크린 키패드. PIN은 숫자 전용,
길이 자유. 설정·변경은 SQL로만(앱 UI 없음 — 사용자 결정). 통과는 포그라운드 세션 수명 —
탭이 배경으로 가면 다시 잠기고, 떠 있던 게이트 화면도 복귀 시 다시 잠근다. PIN 미설정
기기는 게이트 없이 오늘과 똑같이 동작한다. 근거: `specs/2026-08-12-sync-phase2b-pin-design.md`,
게이트 소유자: `src/main.ts` + `src/ui.ts`.

**기기 등록**: 초대 기반, **상한 5대**(사용자 결정 — 성능 예산 아님). 상한 권위는 서버.
관리 화면(`#/manage`)에서 목록·해제, 해제된 기기는 「다시 연결하기」로 복귀. 근거:
`specs/2026-08-13-device-cap-manage-design.md`.

## 7. 운영

- **배포**: `main`에 push = 배포. GitHub Actions가 prettier → test → build → Pages.
  하나라도 실패하면 배포 안 됨. 모든 main 커밋은 단독 배포 가능해야 한다
- **머지**: PR은 squash 전용(레포 설정으로 잠금). PR 제목이 곧 main 커밋 메시지
- **작업 흐름**: 스펙(Fable 5) → `/grill-me` → 적대적 리뷰 → 구현계획·구현(Opus 5).
  원문: `~/.claude/CLAUDE.md`
- **테스트**: 순수 로직은 `src/engine/`에, 예외로 저장·동기화·공용 UI 헬퍼
  (`src/data/db.test.ts`·`src/data/sync.test.ts`·`src/ui.test.ts`)도 있다. DOM·화면
  테스트는 하지 않는다(설계 §12) — 화면 간
  어긋남은 단일 출처 export 구조로 막는다
